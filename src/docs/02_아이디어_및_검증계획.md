# 과수 서비스 아이디어 및 검증 계획

작성일: 2026-10-30 · 상태: 탐색 중, 수요와 데이터는 미검증

## 출발점

과원 기록과 기술자료를 연결해 재배 판단을 돕는다는 가설이다. 대상자는 과원을 직접 운영하면서 교육·상담 사이에 의사결정하거나 상담을 준비하는 사람으로 가정한다. 실제 불편, 기록 보유율, 재사용 의향은 아직 확인되지 않았다. 기존 구상과 조사 이력은 [인수인계](01_기존_구상과_인수인계.md)를 참조한다.

## 검토할 방향

| 후보 | 사용자와 상황 | 제공 가치 | 확인할 위험 |
|---|---|---|---|
| 상담 준비 도우미 | 농업인: 증상을 발견하고 전문가에게 문의하기 전 | 증상·작업 이력·확인할 질문을 정리 | 기록이 없거나 상담 준비 자체가 불편하지 않을 수 있음 |
| 기록 기반 근거 탐색 | 기록을 남기는 과원 운영자: 과거 작업과 기술자료를 비교 | 출처, 적용 조건, 관련 기록을 함께 제시 | 기록의 누락·비정형성, 자료의 작목별 부족 |
| 기술자료 탐색 도우미 | 기록이 없는 농업인: 증상이나 작업에 관한 자료를 찾음 | 추가 질문과 출처가 있는 자료 탐색 | 기존 검색·농사로와의 차별성 |
| 상담 업무 지원 | 지도사: 상담 내용을 정리하고 근거 자료를 탐색 | 상담 준비 및 자료 검색 시간 절감 | 현장 업무 흐름·도입 권한·정보 공유 동의 미확인 |

우선 상담 준비와 근거 탐색을 중심으로 인터뷰하되, 실제 불편에 따라 대상을 바꾼다. 일지가 없을 때는 최소한의 상황 입력과 일반 자료 검색이 가능한지 확인한다. 임의로 만든 일지는 실험용으로만 표시하며 실제 농가 데이터의 대체 근거로 쓰지 않는다.

## 주요 판단 항목

- 수요: 최근 실제 문제, 기존 상담·검색에서 남은 불편, 재사용 및 비용 부담 의향을 확인한다.
- 입력 부담: 수첩·사진·파일의 형태, 기록 빈도와 누락, 업로드 및 수정 의향을 확인한다.
- 데이터: 본문 제공 여부, 작목·품종·지역·시기별 범위, 갱신일, 접근 및 재배포·상업적 이용 조건을 확인한다.
- 신뢰와 안전: 원인을 단정하지 않고 출처·날짜·적용 조건·추가 확인사항을 제시한다. 농약이나 긴급한 피해 관련 판단은 최신 공식 지침과 전문가 확인이 필요하다.
- 개인정보: 일지 제공 동의, 접근 제어, 보관·삭제와 외부 모델 전송 여부를 설계한다.
- 운영: 데이터 갱신, 오류 수정, 답변 검토 책임, 호출 제한 및 비용을 확인한다.
- 기술: 관계 탐색이 실제로 도움이 되는지 일반 검색/RAG와 비교한다. 그래프 구축을 성과 자체로 보지 않는다.

## 데이터 확보 우선순위

1. [작목별농업기술정보](https://www.data.go.kr/data/3060743/openapi.do): 기술자료 후보. LINK형이므로 제공기관의 실제 신청 경로·인증·본문 제공 범위 및 조건 확인.
2. [작물 병해충 검색](https://www.data.go.kr/data/15058504/openapi.do): 증상·발생 환경·방제 정보 후보. 포털은 출처표시 및 상업적 이용금지로 표시한다. 활용신청은 개발·운영 자동승인으로 안내되지만, 실제 제공기관 인증 경로와 실응답을 확인해야 한다.
3. [농촌지도사업정보](https://www.data.go.kr/data/15160954/openapi.do): 기존 지원 조사용. 개인 수요를 직접 보여주지는 않는다. 포털에서 해당 API 활용신청 및 승인 상태를 확인한다.
4. [과수 휴면타파시기](https://www.data.go.kr/data/15168306/openapi.do): 사과·배·복숭아의 지역별 예측 정보. 선택한 문제와 관련 있을 때 신청·검증한다. 관측소 예측값을 개별 과원의 실측값으로 취급하지 않는다.

[농사로 OpenAPI](https://www.nongsaro.go.kr/portal/ps/psz/psza/contentMain.ps?menuId=PS00191)는 본인인증, 신청, 승인 후 별도 키 발급을 안내한다. 공공데이터포털 키와 같다고 가정하지 않는다. 각 API는 목록/상세 응답, 본문, 페이지네이션, 오류, 라이선스를 실험하고 확인일과 결과를 기록한다. 아직 실호출하지 않았다.

## 실행 순서와 판단 기준

1. **문제 탐색:** 과원 운영자와 지도사에게 최근 실제 사례와 기존 해결 방법을 묻는다. 후보별 각 5명은 모집 목표일 뿐 통계적 대표 표본이 아니다. 반복되는 문제와 기록 유무를 정리한다.
2. **데이터 실사:** 인증 후 우선 API를 소량 호출하고 작목 하나와 대표 질문 몇 개에 대해 필요한 본문·조건·출처가 있는지 확인한다. 부족하면 제공기관 자료나 사용자 동의 자료를 조사하고, 확보 불가 시 범위를 축소한다.
3. **작은 시제품:** 인터뷰와 데이터 실사로 작목·상황 하나를 선택한다. 기록 없는 경우와 있는 경우를 모두 시험하고, 답변에 근거와 불확실성을 표시한다.
4. **비교 평가:** 동일한 질문과 자료로 일반 검색/RAG와 Graph RAG를 비교한다. 근거 적합성, 누락·잘못된 연결, 답변 시간, 사용자 유용성 및 입력 부담을 기록한다. 소수의 사례는 탐색 결과로만 해석한다.
5. **결정:** 사용자가 반복해서 겪는 불편, 이용 가능한 근거, 신뢰할 수 있는 결과가 함께 확보되면 확대한다. 어느 하나라도 부족하면 대상·문제·데이터를 바꾸거나 중단한다.

## 인증키 취급

키는 채팅이나 문서에 적지 않는다. 로컬 환경변수 또는 Git에서 제외된 `.env`에 보관하며 실제 호출 전 해당 API의 신청 및 인증 방식을 확인한다. 실응답에는 개인 정보가 포함될 수 있으므로 공개 저장 여부를 검토한다.
