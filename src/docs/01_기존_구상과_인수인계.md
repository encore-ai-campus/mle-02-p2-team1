# 과수 Graph RAG 서비스 — 세션 인수인계

작성일: 2026-10-30 (한국 시간)  
상태: 아이디어 및 타깃 가설을 정리하고, 공공데이터와 API 연계 가능성을 조사한 단계

## 1. 지금까지의 목표

과수 재배 농가의 **재배일지와 농업기술문서를 연결해 재배 판단을 돕는 서비스**를 구상하고 있다. 사용자가 평소 작업·증상 등을 기록해두면, 질문할 때 해당 일지를 매번 다시 입력하지 않아도 기존 기록과 관련 기술문서를 함께 검색하는 구조다.

대화 중 서비스 제안서를 A4 한 페이지 PDF로 여러 차례 수정했고, 이후 기존의 교육·상담 서비스가 이미 제공되고 있다는 점을 고려해 **실제 수요와 타깃을 다시 검증**하기로 했다. 가장 최근에는 공공데이터포털에서 관련 통계·농업기술 API를 찾아보고 호출 준비를 했다.

## 2. 서비스 개념

### 제안하는 사용 흐름

1. 농업인이 평소 재배일지를 기록하거나 기존 일지 파일을 업로드한다.
2. 일지에서 작물, 구역, 날짜, 작업, 관찰 증상 등의 정보를 추출해 연결한다. 추출 결과는 확인할 수 있어야 한다.
3. 농업기술문서에서 작물, 증상, 생육단계, 관리 방법과 적용 조건을 추출해 관련 정보와 연결한다.
4. 농업인이 자연어로 질문하면 기존 일지와 연결된 기술문서를 검색한다.
5. 결과로 **관련 기록, 문서 근거, 적용 조건, 추가로 확인할 사항**을 제시한다.

Graph RAG는 기록과 문서의 관계를 따라 관련 근거를 찾는 데 사용하는 구상이다. 그래프 구축이나 연관관계만으로 실제 원인을 확정할 수는 없다. 일지 활용이나 출처 표시가 Graph RAG에서만 가능한 것도 아니므로, 일반 RAG와 비교해 추가 효과를 검증해야 한다.

### 검색할 기술자료 후보

- 작목별 재배기술 길잡이·매뉴얼
- 병해충의 발생 환경·증상·관리 자료
- 생리장해 자료
- 양수분·관수 관리 지침
- 필요할 때 연계할 지역별 과수 생육 관련 정보

이 목록은 서비스 설계 후보이며, **각 자료의 본문이 실제 API 응답에 포함되는지, 과수 작목·품종과 재배 조건별로 충분한지 아직 실응답 검증을 하지 않았다.**

### 사용자가 실제로 할 법한 질문 예시

- “감귤 잎이 노래지는데 영양제를 더 줘야 하나요?”
- “비 온 뒤 포도가 터지기 시작했어요. 지금 뭘 해야 하나요?”
- “사과 색이 작년보다 안 나요. 제가 작업을 빠뜨린 게 있나요?”

앞선 예시에서 잎이 노랗다는 말만으로 최근 시비·관수 기록부터 찾는 것은 원인을 미리 가정한다는 사용자 지적이 있었다. 적절한 흐름은 **증상 관련 자료와 구분 기준 확인 → 필요한 추가 질문 → 관련성이 확인된 일지·기술문서 연결 → 확인사항 및 근거 제시**다. 질문·기록·문서를 상황에 따라 함께 탐색할 수 있으며, 특정 기록이 모든 사례의 원인이라고 단정하지 않는다.

## 3. 타깃 사용자 — 최신 가설

기존 PDF에는 ‘바로 상담할 전문가가 없는 초보 과수 농업인’이라고 적혀 있지만, 사용자는 현장 지도·교육이 이미 이뤄지고 있고 초보자가 얼마나 되는지도 불확실하다고 지적했다. **이후 대화에서 재정의한 최신 가설은 아래와 같으며, 아직 PDF에는 반영하지 않았다.**

> 교육·현장지도를 받으며 과원을 직접 운영하지만, 작업 기록과 기술자료를 연결해 재배 판단에 활용하기 어려운 농업인.

초기 검증 대상은 다음 특성을 갖는 과수 재배 책임자다.

- 농업기술센터, 교육, 멘토 등 기존 지원을 이용했거나 알고 있다.
- 직접 재배 작업을 결정하고, 교육·상담 사이 또는 상담 후에도 판단해야 할 문제가 생긴다.
- 수첩·파일·앱 등으로 작업이나 증상 기록을 남겨두고, 그 기록을 활용할 의향이 있다.
- 과거 기록 비교, 교육내용 적용 조건 확인, 상담 준비 중 실제로 해결되지 않은 불편이 있다.

연령이나 ‘청년농’ 여부만으로 대상자를 제한하지 않는다. 우선 인터뷰할 후보는 **① 교육 수료 후 독립 운영하는 농업인, ② 과원을 승계해 판단을 맡기 시작한 운영자, ③ 새 작목·품종·재배방식으로 전환한 농업인**이다. 교육 담당자는 초기 최종 사용자라기보다 모집·현장 검증 협력자 후보로 본다.

기존 교육·상담이 충분하고 기록을 대조할 불편도 없다면 이 서비스의 필요성은 낮을 수 있다. ‘초보자가 많다’거나 ‘농가 대부분이 서비스를 안다/모른다’는 식으로 확정하지 말고 조사한다.

## 4. 수요 조사에서 확인할 질문

- 최근 재배 중 어려웠던 문제는 무엇이었고, 당시 누구에게 묻거나 어디를 검색했는가?
- 기존 교육·현장지도·상담으로 해결된 부분과 남은 어려움은 무엇인가?
- 작업일지는 실제로 어떤 형식으로 얼마나 자주 작성하는가? 예전 기록을 다시 찾는가?
- 상담 전에 기록을 정리하거나, 상담 후 자신의 재배 조건에 적용하는 데 불편이 있는가?
- 시범 결과가 기존의 검색·전문가 상담보다 유용하며, 기록 제공 부담을 감수하고 재사용할 의향이 있는가?

초기 아이디어로 세 후보 집단별 각 5명 인터뷰를 제안했으나, 아직 실제 모집·인터뷰는 진행하지 않았다. 자료의 규모와 참여율은 잠재 수요의 **간접 지표**이며 이 서비스의 이용 의사·시장 규모로 바로 환산하지 않는다.

## 6. API 호출 준비 상태

농촌지도사업 목록 API의 공공데이터포털 Swagger 화면에서 확인한 명세:

- URL: `https://apis.data.go.kr/1390000/extension/getExtensionList`
- 방식: GET, JSON 응답
- 필수: `serviceKey`
- 선택: `gdnbsYear`(사업연도), `gdnbsName`(사업명), `atptCenterCode`(시도센터코드), `centerCode`(센터코드), `pageNo`, `pageSize`
- 같은 서비스에서 지역 기관 코드 및 사업 상세 조회 기능도 안내됨.

조회용 파이썬 파일:

`/Users/anna/Documents/Codex/2026-10-30/new-chat/outputs/농촌지도사업_API_조회.py`

실행 예시:

```bash
python3 "/Users/anna/Documents/Codex/2026-10-30/new-chat/outputs/농촌지도사업_API_조회.py" --year 2025 --keyword 과수
```

실행하면 공공데이터포털 **일반 인증키(Decoding)**를 터미널에서 가려 입력할 수 있다. 또는 `PUBLIC_DATA_API_KEY` 환경변수를 사용한다. `--output`으로 응답 JSON을 저장할 수 있다. 키를 채팅이나 전달 문서에 적지 않는다.

**검증 상태:** 스크립트 문법 및 모의 응답·키 인코딩 검사는 통과했다. 실제 인증키가 없어 API 실호출, 응답 내용, 검색어별 데이터 건수는 검증하지 못했다. 활용신청 후 실제 응답과 페이지 처리 방식을 확인해야 한다. 스크립트는 기본적으로 **한 페이지**만 조회한다.

## 8. 다음 세션에서 이어갈 일

1. 사용자의 목적에 맞춰 수요 조사에 필요한 통계표의 **정확한 표명·분류·연도·과수 여부**를 확인한다. 총 귀농가구 수를 과수 초보자 수로 오인하지 않는다.
2. 공공데이터포털에서 농촌지도사업 API 활용신청 및 인증키가 준비되면, 위 스크립트로 실제 응답을 확인한다. 인증키는 사용자 본인이 안전하게 입력한다.
3. 농사로 작목별 기술정보와 병해충 API의 실제 엔드포인트·응답 본문·라이선스를 확인한다. 현재는 카탈로그와 제공기관 안내만 확인했다.
4. 실제 농가 인터뷰와 가능하면 시범 사용으로 기존 교육·상담 이후에도 남는 불편과 일지 작성 부담을 검증한다.
5. 사용자가 요청하거나 작업 흐름상 필요하면 제안서의 타깃과 서비스 가치를 **최신 가설에 맞춰** 갱신한다. 아직 수요가 입증된 것처럼 쓰지 않는다.
