# 제2차 Graph RAG 아이디어 회의

날짜: 2026-10-30 · 상태: 독립 제안과 교차 검토 완료 · 서비스 미선정

## 진행과 모델

사용자 요청으로 진행 중이던 Sol 에이전트를 중단하고 새 Terra 에이전트로 재시작했다. 보강된 역할 지침을 각 에이전트에 읽도록 지시했다. 문제 탐색가와 비판적 검토자는 `gpt-6.1-terra` / `high`, 데이터 조사자는 `gpt-6.1-terra` / `medium`을 사용했다. 이전 회의는 참고 자료로만 취급했다.

## 독립 제안 — 문제 탐색가

아래 문제의 빈도, 사용자 수요, 데이터 접근과 구매 의사는 미검증 가설이다.

1. **제조 설비의 부품 변경 영향 확인:** 정비 담당자가 단종 부품을 교체할 때 부품→설비→정비 작업→대체품 승인 조건을 추적한다. BOM 단일 조회는 DB로 충분할 수 있으며 실제 BOM·승인 이력과 현장 전문가가 필요하다. 미확인 호환성을 단정하면 위험하다.
2. **고객지원 장애·변경 이력:** 담당자가 티켓, 제품 버전, 릴리스와 장애 기록의 명시적 연결 근거를 찾는다. 단일 오류 코드의 문서 검색은 일반 검색으로 충분할 수 있다. 고객 정보 접근과 사건의 인과 오인이 위험이다.
3. **연구실 실험 재현·변경 이력:** 연구원이 두 실험의 실행 기록, 프로토콜 버전, 시약과 코드 차이를 확인한다. 노트 접근과 실행별 ID가 필요하며 기록이 없으면 조건이나 원인을 추정하지 않는다.

## 데이터 조사 — 데이터 조사자

- **제조:** [NIST 제조 데이터 모델 문서](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=822307)는 BOM 등의 모델을 설명한다. 실제 기업의 BOM·승인 이력 데이터셋은 아니다. 합성 BOM은 관계 질의만 실험할 수 있고 현장 효용이나 안전성을 입증하지 못한다.
- **소프트웨어:** [GitHub 이슈 타임라인 API](https://docs.github.com/en/rest/issues/timeline)와 [호출 제한](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)을 확인했다. 공개 이슈·PR·릴리스는 축소된 기술 실험 후보이나 기업 고객지원 티켓을 대표하지 않는다. 명시적 링크와 개별 이슈·댓글의 이용 조건은 표본별로 확인해야 한다.
- **연구:** [Zenodo REST API](https://developers.zenodo.org/)와 [DOI 버전 설명](https://zenodo.org/record/1256592/files/zenodo-doi-versioning.pdf?download=1)은 공개 기록과 버전 탐색의 출발점이다. 개별 기록의 프로토콜·코드 연결과 파일별 이용 조건은 미확인이고 연구실 내부 실패·수행 기록은 대체하지 않는다.

위 내용은 공식 문서 확인 수준이다. 실제 API 호출, 표본별 연결률·결손률, 이용 조건 및 사용자 수요는 검증하지 않았다.

## 교차 검토와 수정

비판적 검토자는 제조와 연구실 후보의 핵심 관계가 내부 자료에 의존하므로 권한과 전문가 평가가 확보될 때까지 보류를 제안했다. 정형 BOM은 관계형 DB와 재귀 질의도 강한 대안이다. 연구 기록을 근거 없이 실행 지시로 바꾸는 것은 위험하다.

고객지원 후보는 공개 소프트웨어 이슈→명시된 수정 PR→릴리스의 **근거 탐색**으로 축소할 수 있다는 의견을 냈다. 공개 이슈 검색이 이미 충분할 수 있으며, 공개 자료가 실제 B2B 지원 수요를 검증하지는 못한다.

문제 탐색가는 제조·연구실의 보류와 소프트웨어 후보 축소에 동의했다. 소프트웨어 운영자·유지보수자의 반복 질문은 아직 가설이며, 한 프로젝트의 명시적 연결을 먼저 확인하고 없는 관계는 미확인으로 처리하자고 제안했다.

비판적 검토자는 공개자료 우선 조건에서 **지원사업 공고 근거·정정 비교, 지역 공사·통제 영향, 공개 소프트웨어 이슈·릴리스 근거 탐색**을 우선 실사할 후보로 제안했다. 앞의 두 후보는 이전 회의에서 이어진 가설이다. 이는 사용자 검증이나 실데이터 실사를 마친 순위가 아니다. 공연 협업과 법령 변경 탐색은 추가 검토 후보로 남겼다.

## 비교 실험 제안

같은 시점과 접근권의 문서·질문을 고정해 키워드 검색, 일반 RAG, Graph RAG를 비교하고, 적절하면 SQL이나 GIS도 대조한다. 단일 문서, 다단계 관계, 시점 변경·상충, 근거가 없는 질문을 포함한다. 원문 위치와 기준일을 포함한 정답표를 사람이 검토하고 근거 적합성, 관계 오류, 누락, 보류 적절성, 시간·운영 비용을 기록한다. 소수 표본은 탐색적 결과로만 해석한다.

## 다음 확인 과제

1. 공개 프로젝트 하나에서 종료 이슈와 수정 PR, 릴리스의 **명시적** 연결이 실제로 존재하는지 표본 확인 및 이용 조건 확인.
2. 지원사업 공고의 원문·정정 이력과 공사·통제의 공간·시간 연결을 각각 소량 실사.
3. 후보별 사용자 실제 사례와 현재 해결 방법을 조사하고, 충분한 관계 자료가 없거나 단순 대안과 효용 차이가 없으면 축소 또는 보류.
