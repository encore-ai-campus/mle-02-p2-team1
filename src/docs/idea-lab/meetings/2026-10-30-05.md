# 제5차 문제를 해결하는 과수 서비스 회의

날짜: 2026-10-30 · 상태: 네 역할 교차 검토 완료 · 수요와 실제 효과 미검증

## 회의 목적

아이디어 에이전트 지침을 수정해 후보마다 사용자 문제와 이를 해결하는 서비스를 명확한 문장으로 제시했다. 아이디어·시장·비판·데이터 네 역할이 Terra로 참여했으며 동시 실행 제한에 따라 순차 실행과 교차 전달을 했다. 아래 사용 장면과 기대 효과는 가상 예시 및 가설이다.

## 후보 1. 거래처별 출하 준비 서비스

**과수 출하 담당자가 납품처마다 다른 조건과 마감일을 확인하다 준비를 놓치는 문제를 해결하기 위해, 거래처 안내문에서 확인된 준비사항과 미확인 조건을 출하별로 정리해 주는 서비스.**

- 문제: 거래처 문자·안내문과 포장재 발주 내역을 오가며 품목·포장·납기 조건을 확인하는 부담이 있을 수 있다. 반복 빈도와 실제 손실은 미확인.
- 서비스: 거래처·출하일과 직접 받은 최신 안내문을 선택하면 명시된 포장·납기 조건을 원문·시점과 함께 표시한다. 미기재·상충 항목은 확인 대상으로 남기고, 담당자가 거래처에 문의하거나 완료 여부를 표시한다.
- 가상 사례: 사과 출하 전 두 거래처 문자에서 각각의 포장 조건을 확인하고 불명확한 납기를 문의한다.
- 기존 대안: 문자 검색, 종이·엑셀 체크리스트, 거래처 전화. 기존 방식이 충분하거나 거래처가 한 곳이면 필요성이 낮을 수 있다.
- 데이터: 개별 거래처의 최신 안내문은 당사자 제공과 사용권 확인이 필요하다. [aT 온라인 도매시장 거래정보](https://www.data.go.kr/data/15141811/openapi.do)는 품목·수량·가격 등의 공개 거래정보이지 개별 계약·출하 조건을 제공한다는 근거가 아니다. 실 API 호출은 하지 않았다.
- 실험: 최근 실제 출하 사례와 허락된 동일 안내문으로 기존 방식과 비교해 조건·마감의 정확성, 누락, 입력·검토 시간과 재사용을 확인한다. 자료가 없으면 조건을 추정하지 않는다.

## 후보 2. 공동작업 일정 조율 서비스

**과수원 작업을 함께 조율하는 운영자가 작업 일정과 참여 가능한 인원을 맞추기 어려운 문제를 해결하기 위해, 필요한 작업과 참여 가능 시간을 모아 일정을 확정할 수 있게 해 주는 서비스.**

- 문제: 수확·전정에 필요한 인원과 시간을 전화·메시지로 확인하고 변동을 다시 전달해야 할 수 있다. 실제 빈도와 부담은 미확인.
- 서비스: 운영자가 작업·장소·희망일·필요 인원을 적고 참여자가 가능 시간을 남기면 부족 인원과 미응답을 표시한다. 운영자는 미응답자를 확인하고 일정을 확정한다.
- 가상 사례: 배 수확 전 날짜별 부족 인원을 확인해 필요한 인력을 추가 섭외한다.
- 기존 대안: 전화·단체 채팅·공유 달력. 참여자의 추가 응답 부담이 절약보다 크거나 고정 인력만 쓰면 불필요할 수 있다.
- 데이터: 참여자 일정·응답은 당사자의 입력과 동의가 필요하다. 공개 날씨 정보는 참고자료일 뿐 개인별 가용시간이 아니다. 연락처·위치 접근권과 삭제를 설계한다.
- 실험: 최근 공동작업 사례에서 기존 방식과 간단한 수동 응답표를 비교해 연락 횟수, 확정 시간, 변경 전달 오류와 참여자 부담을 확인한다.
- 기술 판단: 일정 DB와 규칙·채팅으로 충분할 가능성이 높아 Graph RAG 필요성은 약하다.

## 후보 3. 재해 신고 준비 서비스

**재해를 겪은 과수 농가가 피해 신고나 상담에 필요한 자료를 빠뜨리지 않고 준비하기 위해, 해당 지역의 실제 안내문을 바탕으로 보유 자료와 확인할 항목을 정리해 주는 서비스.**

- 문제: 재해 후 사진, 피해 위치·시점과 기관 안내를 따로 확인해야 할 수 있다. 발생 빈도와 실제 불편은 지역별로 미확인.
- 서비스: 재해 유형·지역·발생일과 해당 기관의 최신 안내문, 동의한 사진을 선택하면 공고에 명시된 준비 항목과 미확인 사항을 원문·시점과 함께 보여준다. 농가는 부족한 정보를 담당 기관에 문의한다. 접수·지원 자격·보상은 확정하지 않는다.
- 가상 사례: 우박 뒤 안내문이 필지 정보와 사진을 요구하면 보유 자료를 확인하고 불명확한 항목을 기관에 묻는다.
- 기존 대안: 지자체·보험사 전화 및 안내문, 사진첩. 기관 안내가 충분하거나 자료 확보가 오히려 부담이면 불필요할 수 있다.
- 데이터: 지자체별 요건과 기한이 다를 수 있다. [광양시의 2025년 호우 신고 공고](https://gwangyang.go.kr/jares/board.es?act=view&bid=0008&list_no=186071&mid=a50701000000&nPage=130)는 사진 등 요구사항을 명시한다. 이는 과거 사례로 현재 기한이 아니다. 다른 공고도 개별 권리·현재성과 적용 범위를 확인해야 한다. 사진·위치 정보 사용은 동의가 필요하다.
- 실험: 최근 실제 신고 경험과 해당 기관의 안내를 바탕으로 기존 전화·안내문 방식과 자료 정리 시제품의 준비 항목 정확성·누락·입력 부담을 기관 담당자와 확인한다. 최신 공고가 없으면 기관 확인이 필요하다고 표시한다.

## 시장·비판·데이터 교차 검토

시장 검증가는 세 후보의 최종 사용자와 구매·도입 결정자, 자료 제공자를 따로 검증해야 한다고 했다. 출하는 농가·선별장 담당자와 거래처, 공동작업은 주최자와 참여자, 재해는 농가와 기관 담당자를 각각 인터뷰할 수 있으나 구매자는 모두 미확인이다. 최근 실제 사례, 대안 사용, 행동·입력 부담·재사용을 관찰하며 편의 표본을 시장 규모로 일반화하지 않는다.

비판적 검토자는 출하의 거래처·품목·시즌과 개정본 혼동, 공동작업의 미응답·변경 전달, 재해의 지역·사건·기한 오인을 주요 위험으로 지적했다. 원문·적용 대상·시점을 남기고 불명확하거나 상충하는 항목은 확인하도록 했다. Graph RAG는 출하와 재해에서 복수 문서 관계 탐색에 도움이 될 수 있다는 가설이며 동일 자료의 단순 검색·일반 RAG와 비교가 필요하다.

데이터 조사자는 개별 거래 조건, 개인 일정, 개별 피해 사실을 공공 통계나 기상정보가 대체하지 못한다고 확인했다. 지역별 공고의 실제 본문 사례는 확인했으나 공고 API 실응답과 첨부 파일, 세부 이용조건은 확인하지 않았다.

아이디어 탐색가는 반론을 반영해 각 서비스에서 미확인을 추정하지 않도록 수정했고 공동작업에 Graph RAG를 전제하지 않았다. 사용자 수요, 이용 빈도, 비용 지불 의사, 자료 제공 의사는 아직 가설이다.

## 다음 검증

세 후보에 관해 최근 실제 사례를 가진 농가·출하 담당자·작업 참여자·기관 담당자를 적절히 모집하고 기존 방식으로 처리한 과정을 먼저 확인한다. 시장 검증가가 제안한 잠정 저비용 순서는 공동작업의 수동 조율 → 동의받은 출하 안내문 확인 → 기관 공고가 확인된 재해 사례 재현이다. 이는 자료 확보 난이도에 따른 순서이며 가치나 수요의 순위가 아니다. 실제 불편이 없거나 기존 방식이 충분하면 해당 후보를 보류한다.
