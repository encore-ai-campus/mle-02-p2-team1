# 데이터 검증 작업 가이드

담당: 성현 · 기준일: 2026-11-06

자동으로 모은 데이터가 원문과 맞는지 사람이 확인하는 작업입니다. 이 결과는 데이터 수정과 발표의 품질 근거로 사용합니다. 코드 작성은 필요 없습니다. Git 명령은 VS Code 터미널에서 안내된 대로 실행합니다. Windows는 터미널 종류를 Git Bash로 선택합니다.

## 작업 목록

| 번호 | 작업 | 건수 | 시작 조건 | 결과 파일 |
|---|---|---|---|---|
| 작업 1 | 재무 자료 대조 | 14개 값 | 바로 시작 | `data/review/financials_check.csv` |
| 작업 2 | 기업 정보 대조 | 21개 값 | 바로 시작 | `data/review/company_info_check.csv` |
| 작업 3 | 뉴스 관련성 판정 | 191건 | 표본 파일 수령 후 | `data/review/news_relevance.csv` |
| 작업 4 | 대표 질문 근거 찾기 | 질문당 3건 | 대표 질문 확정 후 | `data/review/question_evidence.csv` |
| 작업 5 | 추출 관계 판정 | 30건 | 관계 추출 결과 수령 후 | `data/review/claim_review.csv` |

작업은 하나씩 끝내고, 작업마다 브랜치를 새로 만들어 PR을 올립니다.

## 공통 규칙

1. **원문을 직접 보고 판정합니다.** 이 작업의 가치는 사람이 원문을 확인했다는 데 있습니다. AI 요약이나 AI 판정으로 대신하지 않습니다.
2. **모르면 추측하지 않습니다.** 찾을 수 없으면 `not_found`, 판단이 어려우면 `note`에 이유를 적고 팀에 묻습니다.
3. **기사 문장을 복사하지 않습니다.** 제출 CSV에는 ID, 판정, 짧은 이유만 적습니다. 기사 제목과 문장은 넣지 않습니다. 저장소가 공개 상태일 수 있습니다.
4. **원본 데이터를 고치지 않습니다.** 틀린 값을 찾으면 CSV에 기록합니다. `data/collected/` 파일은 수정하지 않습니다.
5. **CSV는 Excel에서 편집한 뒤 `CSV UTF-8`로 저장합니다.** 한글이 깨지지 않습니다.

## 작업 3. 뉴스 관련성 판정

수집한 뉴스가 해당 기업에 관한 기사가 맞는지 표본으로 확인합니다. 이 결과로 뉴스 데이터의 품질을 숫자로 말할 수 있고, 불필요한 기사를 걸러낼 기준을 정할 수 있습니다.

### 표본 받기

개발 담당에게 `news_review_sample.csv`를 받습니다. 기업별 무작위 30건과 퍼시픽테크를 언급한 후보 기사 11건, 총 191건입니다.

이 파일에는 기사 제목과 링크가 있으므로 저장소 밖에 두고 Excel로 편집합니다.

### 판정 기준

각 행의 `original_url`을 열어 기사를 읽고, `company_id` **기업을 기준으로** 판정합니다.

| 값 | 기준 | 예 |
|---|---|---|
| `core` | 기업이 기사의 주요 주제 | 기업의 신제품, 실적, 경영 소식 |
| `mention` | 기업이 실제로 나오지만 주제는 아님 | 행사 참여사 나열, 업계 기사 속 한 문단 |
| `unrelated` | 해당 기업과 관계없음 | 이름만 같은 다른 대상, 기업이 나오지 않음 |
| `broken` | 판단할 수 없음 | 링크 삭제, 본문 대신 광고나 메뉴만 있음 |

`core`와 `mention` 중 헷갈리면 이렇게 판단합니다. **기업 이름을 빼면 기사가 성립하지 않으면 `core`, 성립하면 `mention`입니다.**

`reason`에는 "행사 참여사로만 언급"처럼 내 말로 짧게 적습니다.

### 완료 기준

- [ ] 191행 모두 `label`을 채웠다
- [ ] `mention`, `unrelated`, `broken`은 `reason`을 적었다
- [ ] 판단이 어려웠던 사례를 PR에 적었다
- [ ] `title`, `original_url` 열을 지우고 `data/review/news_relevance.csv`로 저장했다

제출 파일의 열은 `sample_id`, `company_id`, `document_id`, `label`, `reason`입니다.

PR 본문에 기업별 집계를 넣습니다.

| 기업 | core | mention | unrelated | broken |
|---|---:|---:|---:|---:|
| 아모레퍼시픽 | | | | |

표본 결과는 전체 뉴스의 정확도가 아닙니다. "기업별 무작위 30건을 검토한 결과"라고 적습니다.

## 작업 5. 추출 관계 판정

AI가 추출한 관계가 맞는지 판정합니다. 개발 담당에게 표본 30건을 `claim_id`, 주어, 관계, 목적어, 근거 문장, 기사 링크가 있는 파일로 받습니다.

| 값 | 기준 |
|---|---|
| `correct` | 근거 문장이 관계를 분명히 뒷받침함 |
| `partial` | 대체로 맞지만 주어, 대상, 시점, 관계 종류 중 일부가 부정확함 |
| `wrong` | 근거 문장으로 뒷받침되지 않음 |
| `unclear` | 기사 전체를 봐도 판단하기 어려움 |

관계 종류는 다음과 같습니다.

| 관계 | 의미 | 관계 | 의미 |
|---|---|---|---|
| `OWNS` | 소유함 | `LEADS` | 이끎 |
| `OPERATES` | 운영함 | `LAUNCHED` | 출시함 |
| `PARTNERS_WITH` | 협력함 | `PARTICIPATED_IN` | 참여함 |
| `ACQUIRED` | 인수함 | `ANNOUNCED` | 발표함 |
| `INVESTED_IN` | 투자함 | `RELATED_TO` | 그 외 관련됨 |

판정할 때 확인할 사항은 다음과 같습니다.

- 주어와 목적어의 방향이 맞나요? 인수한 쪽과 인수된 쪽이 바뀌면 `wrong`입니다.
- 계획을 완료된 사실처럼 표시했나요? 그렇다면 `partial`입니다.
- 근거 문장에 그 내용이 실제로 있나요? 없으면 `wrong`입니다.

```csv
claim_id,label,reason
,,
```

### 완료 기준

- [ ] 30건을 모두 판정했다
- [ ] `correct`가 아닌 행은 이유를 적었다

## PR 올리기

작업이 끝나면 아래 순서로 올립니다.

```bash
git add data/review/파일이름.csv
git commit -m "Add review results"
git push -u origin HEAD
```

GitHub에서 PR을 만들고, `CONTRIBUTING.md` 양식을 따릅니다. 제목은 `[성현] 재무 자료 대조`처럼 씁니다.

본문에는 다음 내용을 꼭 넣습니다.

- 검토한 건수와 결과별 건수
- `mismatch`, `unrelated`, `wrong` 사례
- 판단이 어려웠던 사례
- 확인한 출처와 확인 날짜

## 막혔을 때

| 상황 | 대응 |
|---|---|
| 공시 값이 안 보임 | 공시 왼쪽 목차에서 재무제표, 감사보고서 항목을 찾아봅니다 |
| 단위가 헷갈림 | 표 위쪽의 "단위" 문구를 확인합니다 |
| 기사 링크가 열리지 않음 | `broken`으로 기록합니다 |
| 표본 파일이 없음 | 개발 담당에게 요청합니다 |
| 판단 기준이 없는 사례 | `note`에 적고 PR에서 질문합니다 |
