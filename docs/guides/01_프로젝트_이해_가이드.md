# 프로젝트 이해 가이드

담당: 수연 · 기준일: 2026-11-06

이 문서는 프로젝트 전체 흐름을 이해하고, 그 내용을 발표 자료로 옮기기 위한 안내서입니다. 위에서부터 순서대로 따라가면 됩니다. 코드를 고칠 필요는 없습니다.

## 진행 순서

- [ ] 1단계: 프로젝트가 무엇인지 설명할 수 있다
- [ ] 2단계: 핵심 용어 7개를 내 말로 설명할 수 있다
- [ ] 3단계: 실제 데이터 파일을 열어 본다
- [ ] 4단계: 기사 한 건이 그래프가 되는 과정을 따라간다
- [ ] 5단계: 코드 위치를 안다
- [ ] 6단계: 이해 확인을 통과한다
- [ ] 7단계: 발표 자료를 만든다

## 1단계. 프로젝트 한눈에 보기

**무엇을 만드나요?** 기업에 관한 뉴스와 공시를 모아 기업, 인물, 브랜드, 행사의 관계를 그래프로 연결합니다. 질문을 하면 그 그래프와 원문을 찾아 근거와 함께 답합니다.

**누구를 대상으로 하나요?** 아모레퍼시픽과 관련 기업 7곳입니다.

| 기업 | 기업 ID |
|---|---|
| 아모레퍼시픽 | `COMPANY-AMOREPACIFIC` |
| 이니스프리 | `COMPANY-INNISFREE` |
| 에스쁘아 | `COMPANY-ESPOIR` |
| 에뛰드 | `COMPANY-ETUDE` |
| 퍼시픽테크 | `COMPANY-PACIFICTECH` |
| 아모스프로페셔널 | `COMPANY-AMOSPROFESSIONAL` |
| 코스알엑스 | `COMPANY-COSRX` |

**왜 일반 검색으로는 부족할까요?** 일반 검색은 질문과 비슷한 문서를 찾습니다. "아모레퍼시픽과 연결된 회사들의 최근 협력 관계"처럼 여러 문서를 이어야 하는 질문은 관계를 따라가는 방식이 유리할 수 있습니다. 실제로 더 나은지는 프로젝트에서 비교해 확인할 내용입니다.

## 2단계. 핵심 용어

| 용어 | 쉬운 설명 | 이 프로젝트의 예 |
|---|---|---|
| 지식그래프 | 대상을 점으로, 관계를 선으로 이은 지도 | 아모레퍼시픽 → 참여 → 입법박람회 |
| 노드 | 그래프의 점 | 기업, 기사, 청크 |
| 관계 | 점을 잇는 선 | `PARTICIPATED_IN`(참여함) |
| 청크 | 긴 글을 잘라 놓은 조각 | 기사 1건을 약 1,200자 단위로 자른 것 |
| 임베딩 | 글의 의미를 숫자 목록으로 바꾼 것 | 청크 1개당 숫자 1,536개 |
| RAG | 자료를 먼저 찾고, 그 자료를 근거로 AI가 답하는 방식 | 기사 조각을 찾아 답변에 사용 |
| GraphRAG | RAG에 그래프 관계 탐색을 더한 방식 | 찾은 조각과 연결된 관계까지 함께 사용 |

"인용이 원문에 있다"와 "내용이 사실이다"는 다릅니다. 시스템은 인용 문구가 기사에 그대로 있는지만 자동으로 검사합니다. 그 관계 해석이 맞는지는 사람이 확인해야 합니다. 발표에서도 이 둘을 구분합니다.

## 3단계. 전체 흐름과 데이터

```text
수집 → 정리 → 청크 분할 → 임베딩 → 관계 추출 → 근거 검사 → 그래프 저장 → 질문과 답변
```

| 단계 | 하는 일 | 입력 | 결과 |
|---|---|---|---|
| 수집 | 네이버 뉴스와 공시 자료를 모음 | 기업 목록 | `news.jsonl` 등 |
| 청크 분할 | 기사를 조각으로 나눔 | 기사 본문 | `news_chunks_v1.jsonl` |
| 임베딩 | 조각을 숫자로 바꿔 검색 가능하게 함 | 청크 | Neo4j에 저장 |
| 관계 추출 | AI가 기사에서 관계 후보를 찾음 | 청크 | 관계 후보 파일 |
| 근거 검사 | 인용이 원문에 있는지 확인 | 관계 후보 | 통과 또는 제외 |
| 그래프 저장 | Neo4j에 저장 | 검사 통과 관계 | 그래프 |
| 질문과 답변 | 관련 청크와 관계를 찾아 답변 | 질문 | 출처가 붙은 답변 |

### 데이터 직접 열어 보기

VS Code에서 저장소를 열고 아래 파일을 봅니다. `.jsonl`은 한 줄에 자료 하나가 들어 있는 파일입니다.

| 파일 | 내용 | 먼저 볼 필드 |
|---|---|---|
| `data/collected/companies.jsonl` | 기업 목록 7건 | `company_id`, `legal_name` |
| `data/collected/company_info.jsonl` | 기업 정보 7건 | `industry`, `employee_count` |
| `data/collected/financials.jsonl` | 2025년 재무 7건 | `revenue_krw`, `operating_profit_krw`, `source` |
| `data/collected/news.jsonl` | 뉴스 4,580건 | `document_id`, `title`, `company_ids`, `content` |
| `data/processed/news_chunks_v1.jsonl` | 뉴스 청크 12,309개 | `chunk_id`, `document_id`, `text` |

뉴스와 청크 파일이 보이지 않으면 저장소가 아니라 팀 공유 자료 위치에서 받아 같은 경로에 둡니다. 기사 본문은 이용 조건을 확인하기 전까지 공개 저장소에 올리지 않습니다.

`company_ids`가 왜 목록인지 생각해 보세요. 기사 하나가 여러 기업을 다룰 수 있기 때문입니다. 뉴스 4,580건 중 900건은 두 기업 이상에 연결되어 있습니다.

### 현재 진행 상태 (2026-11-06 기준)

| 단계 | 상태 | 근거 |

| 사람 검증 | 시작 전 | 결과 파일 없음 |
| 일반 검색과의 비교 | 시작 전 | 대표 질문 확정 필요 |

## 4단계. 기사 한 건 따라가기

`NEWS-23178d84642bd6c9` 기사를 예로 듭니다. VS Code 찾기에서 이 ID를 검색해 직접 확인하세요.

1. **기사:** `news.jsonl`에서 찾습니다. 제목은 "[AT 현장] 잔디밭선 '축제', 본회의선 '필버 전쟁'..."이고, `company_ids`는 `COMPANY-AMOREPACIFIC`입니다.
2. **청크:** `news_chunks_v1.jsonl`에서 같은 `document_id`를 찾습니다. 기사가 2개 조각으로 나뉘어 있습니다.
3. **근거 문장:** 본문에서 입법박람회에 아모레퍼시픽 부스가 있었다는 부분을 찾습니다.
4. **관계로 표현:**

   ```text
   (아모레퍼시픽) -[PARTICIPATED_IN]-> (2026 국회 입법박람회)
   근거: 기사 NEWS-23178d84642bd6c9의 해당 문장
   ```

5. **왜 관계 이름을 영어로 고정하나요?** "부스 운영", "부스가 있었음", "참여함"처럼 표현이 제각각이면 검색이 어렵기 때문입니다. `data_code/graph.ipynb`에서 이 예시가 바뀌어 가는 과정을 볼 수 있습니다.

이 기사의 제목에는 아모레퍼시픽이 없습니다. 기업이 기사 주제가 아니라 일부로만 등장할 수도 있다는 뜻입니다. 그래서 수집 결과에는 관련성 검토가 필요합니다.

## 5단계. 코드 위치

코드를 전부 이해할 필요는 없습니다. 무엇이 어디에 있는지만 알면 됩니다.

| 위치 | 역할 |
|---|---|
| `data_code/new.ipynb` | 네이버 뉴스 검색과 본문 수집 |
| `data_code/company_info.ipynb` | 기업 정보 수집 |
| `data_code/financials.ipynb` | 재무 자료 수집 |
| `data_code/graph.ipynb` | 그래프 개념 연습과 청크 분할 |
| `data_code/AuraDB.ipynb` | Neo4j Aura 저장과 임베딩 |
| `src/bulsae/graphrag/pipeline.py` | 관계 추출, 근거 검사, 그래프 저장, 질문 답변 |
| `src/bulsae/graphrag/README.md` | 파일럿 실행 방법 |

읽는 순서는 `graph.ipynb` → `AuraDB.ipynb` → `graphrag/README.md`를 권합니다. 저장소의 노트북에 출력이 없으면 팀 공유 위치의 실행본을 함께 봅니다.

## 6단계. 이해 확인

자료를 보지 않고 **내 말로** 설명합니다. 답을 외울 필요는 없습니다. 팀원에게 5분 정도 설명해 보고, 막힌 부분은 위 단계로 돌아가 다시 봅니다.

1. 이 프로젝트가 풀려는 문제는 무엇인가요?
2. 청크는 왜 필요한가요?
3. 임베딩과 관계 추출의 차이는 무엇인가요?
4. 기사 한 건이 답변의 근거가 되기까지 어떤 단계를 거치나요?
5. 관계 후보가 저장되기 전에 어떤 검사를 받나요? 그 검사로 알 수 없는 것은 무엇인가요?
6. 뉴스가 4,580건인데 기업별 건수의 합이 그보다 많은 이유는 무엇인가요?
7. 현재 완성된 부분과 아직 진행 중인 부분은 무엇인가요?
8. 공개 저장소에 기사 본문을 올리면 안 되는 이유는 무엇인가요?

### 발표 자료로 넘어가는 기준

- [ ] 4단계의 기사를 예로 들어 전체 흐름을 설명할 수 있다
- [ ] 위 8개 질문에 답할 수 있다
- [ ] 완성된 것과 진행 중인 것을 구분해서 말할 수 있다

## 7단계. 발표 자료 만들기

### 목차 초안

1. 프로젝트 소개: 대상 기업과 풀려는 문제
2. 왜 지식그래프인가: 일반 검색과의 차이
3. 데이터: 수집 범위와 건수
4. 시스템 구조: 전체 흐름 그림
5. 기사 한 건의 여정: 기사 → 청크 → 관계 → 근거
6. 품질 관리: 근거 검사와 사람 검토
7. 시연: 대표 질문과 답변
8. 비교 결과: 일반 검색과 GraphRAG
9. 한계와 다음 단계

7~8번은 대표 질문과 비교 결과가 나오면 채웁니다. 나머지부터 만들면 됩니다.

### 표현 주의

| 피할 표현 | 이렇게 표현 |
|---|---|
| 모든 관계가 검증되었습니다 | 인용이 원문에 있는지 자동으로 확인했습니다. 사람 검토는 결과가 나온 뒤 건수와 함께 말합니다 |
