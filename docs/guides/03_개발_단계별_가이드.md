### S1-2. 청크 v2 만들기

`pipeline.py`의 적재 단계는 `start_char`, `end_char`, `content_sha256`을 사용하는데 `news_chunks_v1.jsonl`에는 이 필드가 없습니다. 청크를 새로 자르지 않고 **위치와 해시만 더합니다.** `chunk_id`와 본문이 그대로이므로 Aura에 저장한 임베딩을 다시 쓸 수 있습니다.

전체 12,309개가 원문에서 순서대로 찾아지고, v2 위치로 잘라낸 값이 청크 본문과 모두 일치하는 것을 확인했습니다.

아래 코드를 `private_data/add_chunk_offsets.py`로 저장해 실행합니다.

```python
"""news_chunks_v1에 원문 위치와 해시를 더해 v2를 만든다. 본문과 chunk_id는 바꾸지 않는다."""
import hashlib
import json
from pathlib import Path

NEWS = Path("data/collected/news.jsonl")
V1 = Path("data/processed/news_chunks_v1.jsonl")
V2 = Path("data/processed/news_chunks_v2.jsonl")

contents = {}
with NEWS.open(encoding="utf-8") as file:
    for line in file:
        if line.strip():
            row = json.loads(line)
            contents[row["document_id"]] = row["content"]

next_search = {}
count = 0
with V1.open(encoding="utf-8") as source, V2.open("x", encoding="utf-8") as output:
    for line in source:
        if not line.strip():
            continue
        chunk = json.loads(line)
        content = contents[chunk["document_id"]]
        start = content.find(chunk["text"], next_search.get(chunk["document_id"], 0))
        if start < 0:
            raise ValueError(f"원문에서 찾지 못한 청크: {chunk['chunk_id']}")
        end = start + len(chunk["text"])
        next_search[chunk["document_id"]] = start + 1
        chunk["start_char"] = start
        chunk["end_char"] = end
        chunk["content_sha256"] = hashlib.sha256(content.encode("utf-8")).hexdigest()
        output.write(json.dumps(chunk, ensure_ascii=False) + "\n")
        count += 1
print(f"완료: {count}개")
```

```bash
uv run python private_data/add_chunk_offsets.py
```

### S1-4. 뉴스 검토 표본 만들기와 퍼시픽테크 확인

`companies.jsonl`에는 7개 기업이 있지만 `news.jsonl`에는 퍼시픽테크 기사가 없습니다. 체크포인트에는 후보 1,234건이 있고, 그중 본문에 "퍼시픽테크"가 있는 기사는 11건입니다.

아래 코드를 `private_data/sample_news.py`로 저장해 실행하고, 결과 파일을 팀 비공개 공유 위치로 성현에게 전달합니다. 표본은 항상 같게 나옵니다.

```python
"""기업별 뉴스 30건과 퍼시픽테크 언급 기사를 뽑아 검토표를 만든다. 본문은 넣지 않는다."""
import csv
import json
import random
from pathlib import Path

SEED = 20261106
PER_COMPANY = 30
COLUMNS = ["sample_id", "company_id", "document_id", "title", "original_url",
           "label", "reason"]


def read_jsonl(path):
    with path.open(encoding="utf-8") as file:
        return [json.loads(line) for line in file if line.strip()]


news = read_jsonl(Path("data/collected/news.jsonl"))
company_ids = sorted({company for row in news for company in row["company_ids"]})
rows = []
generator = random.Random(SEED)
for company in company_ids:
    matched = sorted((row for row in news if company in row["company_ids"]),
                     key=lambda row: row["document_id"])
    rows.extend((company, row) for row in generator.sample(matched, PER_COMPANY))

pacific = read_jsonl(Path("data_code/pacifictech/pacifictech_news_checkpoint_additional.jsonl"))
rows.extend(("COMPANY-PACIFICTECH", row) for row in pacific if "퍼시픽테크" in row["content"])

output = Path("private_data/news_review_sample.csv")
with output.open("x", encoding="utf-8-sig", newline="") as file:
    writer = csv.writer(file)
    writer.writerow(COLUMNS)
    for number, (company, row) in enumerate(rows, 1):
        writer.writerow([f"S{number:03d}", company, row["document_id"], row["title"],
                         row["original_url"], "", ""])
print(f"완료: {len(rows)}건 -> {output}")
```

### S2-1. 라벨 맞추기

노트북은 `BulsaeDocument`, `BulsaeChunk`를, `pipeline.py`는 `Document`, `Chunk`, `HAS_CHUNK`와 `id` 속성을 씁니다. 코드를 고치는 대신 기존 노드에 **라벨과 속성을 추가**합니다. 기존 데이터는 삭제되지 않고 임베딩도 그대로 쓸 수 있습니다.

이 Cypher는 아직 실제 DB에서 실행해 보지 않았습니다. Aura Query 화면에서 한 문장씩 실행하고 결과를 확인합니다.

```cypher
MATCH (d:BulsaeDocument)
SET d:Document, d.id = d.document_id, d.url = d.original_url;
```

```cypher
MATCH (c:BulsaeChunk)
SET c:Chunk, c.id = c.chunk_id;
```

```cypher
MATCH (c:BulsaeChunk)
MATCH (d:BulsaeDocument {document_id: c.document_id})
MERGE (d)-[:HAS_CHUNK]->(c);
```

확인 쿼리입니다. `missing`은 0이어야 합니다.

```cypher
MATCH (c:Chunk)
WHERE NOT EXISTS { MATCH (:Document)-[:HAS_CHUNK]->(c) }
RETURN count(c) AS missing;
```

- [ ] 문서 4,580, 청크 12,309, `HAS_CHUNK` 12,309를 확인했다

메모리 오류가 나면 `CALL { ... } IN TRANSACTIONS OF 1000 ROWS` 형식으로 나눠 실행합니다.

벡터 인덱스 `bulsae_chunk_embedding`은 다음 단계의 `load`가 만듭니다. `SHOW INDEXES`에서 `ONLINE` 상태가 된 뒤 `ask`를 실행합니다.

### S2-2. 소량 추출

처음에는 비용이 거의 들지 않게 5개만 실행합니다. 추출 입력은 파일 앞쪽 청크부터 사용합니다.

```bash
uv run python -m bulsae.graphrag.pipeline extract \
  data/processed/news_chunks_v2.jsonl private_data/extracted_5.jsonl --limit 5
```

- [ ] `claims`와 `rejected`를 원문과 비교했다
- [ ] 거부된 이유를 분류했다
- [ ] 필요하면 프롬프트를 고치고 새 출력 파일로 다시 실행했다
- [ ] 문제가 없으면 `--limit 50`으로 늘렸다

출력 파일에 기사 본문이 포함되므로 `private_data/`에만 둡니다. 같은 파일명으로 다시 실행하면 오류가 나도록 되어 있어 새 파일명을 씁니다.

### S2-3. 사람 검토

- [ ] 추출 결과에서 30건을 골라 성현에게 전달했다 (작업 5). 파일에는 `claim_id`, 주어, 관계, 목적어, 근거 문장, 링크를 넣는다
- [ ] 판정 결과를 집계했다: `correct`, `partial`, `wrong`, `unclear`
- [ ] 정확도가 낮으면 프롬프트나 관계 종류를 고치고 다시 소량 실행했다

### S2-4. 적재와 조회

```bash
uv run python -m bulsae.graphrag.pipeline load-structured
uv run python -m bulsae.graphrag.pipeline load private_data/extracted_50.jsonl
uv run python -m bulsae.graphrag.pipeline ask '아모레퍼시픽의 주요 협력 관계는 무엇인가요?'
```

`load`는 청크마다 임베딩을 다시 호출하므로 소량으로 시작합니다.

Aura에서 근거 추적이 되는지 확인합니다.

```cypher
MATCH (claim:Claim)-[:SUBJECT]->(s:Entity),
      (claim)-[:OBJECT]->(o:Entity),
      (claim)-[:SUPPORTED_BY]->(c:Chunk)<-[:HAS_CHUNK]-(d:Document)
RETURN s.name, claim.relation, o.name, claim.evidence, d.title, d.url
LIMIT 10;
```

- [ ] 관계에서 기사 URL까지 연결된다
- [ ] 같은 파일로 `load`를 다시 실행해도 `Claim` 수가 늘지 않는다

### S2 현재 코드의 제약

| 제약 | 영향 | 대응 |
|---|---|---|
| `load-structured`는 아모레퍼시픽만 적재 | 다른 기업의 재무가 그래프에 없음 | 대표 질문에 필요하면 7개사로 확장 |
| 아모레퍼시픽 외 개체는 문서별로 분리 | 같은 회사가 문서마다 다른 노드가 됨 | 관계 탐색이 약해질 수 있으므로 S3 결과를 보고 개체 통합 판단 |
| 추출 프롬프트가 아모레퍼시픽을 우선 | 다른 기업의 관계가 덜 나올 수 있음 | 소량 결과에서 확인 |
| 추출 결과에서 사라진 관계는 재적재해도 남음 | 오래된 관계가 남을 수 있음 | 파일럿 DB에서 작업 |
