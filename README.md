# 기업 관계 인텔리전스 지식그래프

기업과 관련된 정보를 문서에서 수집하고, 기업·인물·사건·전략 등의 관계를 지식그래프로 연결해 탐색하는 팀 프로젝트입니다.

흩어진 자료를 연결하여 기업과 관련된 이슈와 사업 환경을 살펴보고, 원문 근거를 확인할 수 있는 그래프 구축을 목표로 합니다.

> 자료 출처 40개를 목록화했으며, 그중 원본 HTML을 확보한 7개 문서를 1차 전처리했습니다.

> 대표 질문과 최종 온톨로지는 팀 협의가 필요합니다. 이 README의 수치는 현재 확인된 1차 작업 기준이며 팀 전체 수집량을 뜻하지 않습니다.

## 프로젝트 범위

현재 자료 수집은 아래 7개 기업을 대상으로 진행했습니다.

- 이니스프리
- 에스쁘아
- 아모레퍼시픽
- 에뛰드
- 퍼시픽테크
- 아모스프로페셔널
- 코스알엑스

주요 조사 영역은 **사회 이슈, 시장 상황, 기업 전략, 오너·경영진·주주**입니다.

기업 간 관계와 출처에서 확인할 수 있는 관련 정보도 함께 살펴봅니다. 최종 분석 대상과 세부 범위는 팀 협의에 따라 조정할 수 있습니다.

## 목표 흐름

```text
자료 조사 및 원문 확보 (현재 진행 중)
        ↓
본문 정리 및 문단·절 단위 분할 (오늘 할 예정)
        ↓
온톨로지 및 추출 규칙 설계(오늘 할 예정)
        ↓
LLM 기반 개체·관계·속성 추출과 검증
        ↓
개체 정규화 및 Neo4j 적재
        ↓
Cypher 조회와 원문 대조
```

현재는 **자료 조사와 M1 전처리를 진행 중**입니다. 이후 단계는 계획이며, 아직 구현하거나 완료한 것으로 확정하지 않았습니다.

### 자료 수집

- 현재 목록은 **서로 다른 출처 40개**로 정리했습니다. 기업과 조사 영역에 따라 같은 출처가 여러 번 활용될 수 있습니다.
- 목록에는 출처 링크, 관련 내용 요약, 확인 위치와 주의사항이 정리되어 있습니다. 목록 자체가 원문 전체를 저장한 데이터셋은 아닙니다.
- 퍼시픽테크의 직접 사회 이슈와 기업별 최신 지분·임기 정보는 추가 확인이 필요합니다.
- 팀원이 추가 수집한 자료는 향후 통합하고 중복 여부를 확인할 예정입니다.

### M1 문서 전처리

M1에서는 반복 머리말·꼬리말과 불필요한 공백을 정리하고, 문단·절·표 등 문서 구조를 고려해 분할합니다. 기술명·식별자·버전과 관계 설명은 보존하고, 문서 ID·청크 ID·원문 위치를 연결합니다.

| 항목 | 1차 결과 |
|---|---:|
| 전처리한 문서 | 7개 |
| 정제 블록 | 4,978개 |
| 청크 | 934개 |
| 원문 확보 및 전처리 필요 | 33개 |

- 934개 청크 중 **894개가 아모레퍼시픽 2026년 1분기보고서**에서 생성됐습니다. 문서 종류에 따라 청크 수가 크게 다릅니다.
- 문서 ID, 청크 ID, 원문 HTML 위치(XPath), 원본 해시를 연결했습니다.
- 표는 인접 행을 묶고 관련 문맥을 기록했습니다. 표의 단위·기준일이 적용되는 범위는 원문 대조가 필요합니다.
- ID, 블록 참조, 원문 위치 및 본문 변경 등에 대한 자동 검사를 수행했습니다. 자동 검사 통과가 모든 내용의 의미적 정확성을 보장하지는 않습니다.

## 1차 전처리 산출물

아래는 **별도로 전달된 `M1_preprocessing_round1.zip`의 구성**입니다. 팀 저장소에 해당 파일들이 이미 추가되었다는 의미는 아닙니다.

| 경로 | 설명 |
|---|---|
| `먼저읽기.txt` | 처리 범위와 실행 방법, 주의사항 |
| `전처리_전후_예시.html` | 전처리 전후 및 원문 위치 예시 |
| `code/preprocess.py` | 본문 추출, 정리, 블록·청크 생성 코드 |
| `code/validate.py` | 전처리 결과의 연결 및 무결성 검사 코드 |
| `code/acquire.py` | 원문 다운로드 보조 코드. 1차 7개 문서 수집에는 사용하지 않음 |
| `input/manifest.json` | 40개 출처의 메타데이터와 처리 상태 |
| `input/raw/` | 1차 전처리에 사용한 원본 HTML 7개 |
| `output/documents.jsonl` | 문서별 메타데이터와 정제 본문 |
| `output/blocks.jsonl` | 제목·문단·표 행 등으로 분리한 블록 |
| `output/chunks.jsonl` | 추출 단계에서 사용할 수 있는 청크와 출처 연결 정보 |
| `output/before_after.jsonl` | 전처리 전후 예시 데이터 |
| `output/removals.jsonl` | 제외한 내용의 위치와 사유 |
| `output/status.jsonl` | 출처별 처리 상태 |
| `output/summary.json` | 전처리 결과 수량 요약 |
| `review/` | 자동 검사 결과와 별도 검토 기록 |

`chunks.jsonl`은 전처리된 텍스트이며, LLM이 추출한 개체·관계 결과는 아닙니다. JSONL은 이번 M1 산출물을 저장하기 위한 형식이며, 지식그래프 구축에 반드시 필요한 유일한 형식은 아닙니다.

## 다음 작업

1. 팀원과 그래프로 확인할 대표 질문을 정합니다.
2. 7개 문서에서 형식과 내용이 다른 청크를 골라 개체·관계 유형과 속성의 초안을 설계합니다.
3. 추출 프롬프트와 검증 규칙을 작성하고 소규모 청크로 M4 파이프라인을 시험합니다.
4. 나머지 문서의 원문을 확보·전처리하면서 설계와 추출 규칙을 보완합니다.
5. 추출 결과를 정규화하고 Neo4j에 적재한 뒤 질문별 조회와 원문 대조를 진행합니다.

## 협의 및 확인 사항

- 대표 질문, 최종 문서 범위, 온톨로지와 관계 방향은 팀 협의가 필요합니다.
- 원문에서 확인된 사실과 계획·추정·보도를 구분하고, 문서 ID와 근거 위치를 유지합니다.
- 원문과 처리 결과의 저장·공유·외부 모델 전송은 각 출처의 이용 조건을 확인한 뒤 결정합니다.
- 저장소 구조와 최종 실행 환경은 팀이 정한 실제 구성에 맞춰 이 문서를 갱신합니다.
