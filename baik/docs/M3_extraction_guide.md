# M3 뉴스 개체·관계 추출 프롬프트 v0.1

## 목적과 사용 범위
M2 네 파일 스키마 초안을 뉴스 본문에 적용하는 시스템 프롬프트다. 7개 기업과 직접 관련된 내용, 허용 유형·방향, 근거 및 불확실성 처리, JSON 형식을 지정한다. 구조화된 companies/company_info/financials는 원문으로 위장해 LLM에 보내지 않고 별도 검증·M6 매핑 경로를 사용한다.

## 실제 사용 방법
`system_prompt.txt`의 전체 내용을 시스템 메시지로 전달하고, 사용자 메시지에 아래 형식의 JSON 한 건을 넣는다. `primary_text`에는 선별·중복 검사·전처리를 거쳐 생성된 한 청크의 본문을 넣는다. `document_id`, `chunk_id`는 전처리 시 부여한 ID다. 메타데이터는 선택이며 출처 기록용이다. 인접 문맥이 필요할 경우 지금 버전은 지원하지 않으므로 문맥이 포함되도록 청크를 다시 구성하거나 보류한다.

```json
{
  "document_id": "DOC-EXAMPLE-001",
  "chunk_id": "DOC-EXAMPLE-001-C001",
  "primary_text": "에이피 뷰티(AP BEAUTY)가 신제품 ‘듀얼 리페어 리프트 M.D. 크림 미스트’를 출시했다.",
  "metadata": {"title": "예시", "source_url": "https://example.com/article", "company_ids": []}
}
```

위 내용은 사용법을 설명하기 위한 구성 예시다. 검색된 실제 기사나 원문을 대체하지 않는다. 실제 요청을 보내기 전 문서 전송 허용 범위 및 민감정보, 비용을 확인한다. 시스템 프롬프트와 입력 파일 버전·모델명·실행 설정·응답·검토 결과를 기록한다.

## 응답 예시
입력 예시는 대상 기업과의 연관성이 제시되지 않으므로 빈 결과가 안전하다.

```json
{"document_id":"DOC-EXAMPLE-001","chunk_id":"DOC-EXAMPLE-001-C001","entities":[],"relations":[]}
```

에이피 뷰티가 대상 기업과 관련된다는 외부 지식 또는 company_ids만으로는 판단하지 않는다. 실제 기사에 대상 기업과 브랜드의 관련성이 드러나는 경우에는 원문에 근거해 제품→PRODUCT_UNDER_BRAND→브랜드를 추출할 수 있다. 제품·브랜드 관계 자체의 quote도 반드시 청크에 있어야 한다.

## 수동 검토 사례와 한계
- 이니스프리·에스쁘아 제품이 같은 할인 행사에 나열된 기사: 각 제품→브랜드는 후보지만, 두 기업 간 협업은 생성하지 않는다. 행사 연결은 원문이 지지하는 경우만 허용한다.
- 아모레퍼시픽 재무 레코드: 회사→재무 관측을 구조화 매핑한다. 매출과 영업이익, 2025년, 개별, KRW 및 출처를 보존하고 원문과 대조한다.
- 선크림 시험 기사: 현재 뉴스 JSONL의 해당 본문은 링크뿐이므로 추출하지 않는다. 원문을 복구한 뒤 실측 SPF와 표시 SPF, 국가·시험 조건을 구분한다.
- 이벤트 참가·브랜드 운영·제품 출시를 같은 유형의 관계로 강제하지 않는다. 날짜·지분·직책을 확인하지 못하면 null/unknown이다.

## 기존 M4와의 호환성
이 프롬프트는 **새 M2 초안용 계약**이다. 기존 M4는 기존 10개 유형·9개 관계 및 이전 출력 구조를 검증한다. 이 프롬프트의 Regulation·Character, PRODUCT_FEATURED_IN·EVENT_FEATURES·REGULATES와 evidence 객체 등은 기존 M4와 호환된다고 보장할 수 없다. 기존 파이프라인에 바로 교체하지 말고 M4 입력 매핑(primary_text와 text), JSON 파서·스키마·관계 방향·근거 검증 및 M5를 함께 수정·시험해야 한다. 이 패키지는 M4 코드 수정이나 API 호출을 수행하지 않았다.

## 다음 검증
1. 팀과 7개 기업 범위, 기업·브랜드 구별, 신규 관계, 중요도 기준 합의.
2. JSON 스키마, 관계 방향·ID 참조·quote의 primary_text 부분 문자열 여부 검증기 작성.
3. 실제 모델에 소수의 검토된 청크를 전달하고 출력·실패·빈 결과를 구분해 저장.
4. 원문과 대조해 의미 타당성, 누락·오추출·수치·시점·법인/브랜드 오병합을 점검. 부분 문자열 검사는 의미 정확성을 보장하지 않는다.
5. 결과에 따라 M2·M3·M4·M5 계약을 함께 개정한다.

본 결과는 작성된 실제 사용용 프롬프트 초안이다. 실제 API 호출·모델별 호환성·정확도는 아직 검증되지 않았다.

## 기존 M4용 프롬프트

`existing_m4_compatible_prompt.txt`는 통합 2차 패키지의 M4 프롬프트를 그대로 복사한 것이다. 기존 코드의 계약에 맞춰 작성되었으며 이번 M2 확장 내용은 미반영이다. 기존 M4를 사용한다면 해당 패키지의 README, 입력 text·context_chunks, validators와 함께 사용하고 실행 결과를 검증한다.
