## 1. 단계 결과 한눈에 보기

### 1.1 핵심 결과 통계

아래 표는 **집계 단위와 전체 기준이 다르다.** 뉴스 청크의 추출 상태, 추출된 관계의 적재 후보 여부, 후보 관계가 나온 기사의 수를 각각 보여 준다.

| 구분 | 전체 | 이번에 확보·포함 | 아직 처리하지 않았거나 이번에 제외 |
| --- | ---: | ---: | ---: |
| **M4 뉴스 추출** · 청크 기준 | 6,878개 | 성공 **4,757개 (69.2%)** | 실패·대기 **2,121개 (30.8%)** |
| **M5 뉴스 정규화** · 관계 기록 기준 | 20,270건 | 적재 후보 **17,698건 (87.3%)** | 이번 범위 제외 **2,572건 (12.7%)** |
| **M5 뉴스 반영** · 기사 기준 | 4,580건 | 관계 후보가 하나 이상 있는 기사 **2,687건 (58.7%)** | 관계 후보가 없는 기사 **1,893건 (41.3%)** |

| 자료·결과 | 수량 | 의미 |
| --- | ---: | --- |
| 뉴스 관계 후보 | 17,698건 | 기존 연결 1,905건과 후속 처리 15,793건을 보존 |
| 재무·공시 관계 | 28건 | 재무 관계 14건과 공시 지분 관측 14건. 뉴스와 별도 집계 |
| 노드 후보 | 12,247개 | 이번 뉴스 및 재무·공시 관계에 연결된 노드 후보 |
| 추가 확인할 개별 제품·행사 | 576개 | 이번 후보 안에 포함하되 다른 개체와 합치지 않고 보존한 노드 |

> **통계 해석:** 87.3%는 M4 성공분에서 나온 뉴스 관계 중 이번 M5 적재 후보에 포함한 **관계 기록의 비율**이다. 사실 검증 완료율, 모든 원본 기사의 처리율 또는 실제 Neo4j 적재율이 아니다. 17,698건과 28건도 서로 다른 자료의 관계 기록이며, 12,247개와 576개는 노드 수다. 후보에는 잠정 연결과 추가 검토가 필요한 항목이 포함된다.

### 관계 후보가 없는 기사 1,893건의 의미

관계 후보가 없는 기사는 **이번 적재 후보인 뉴스 관계 17,698건에 그 기사를 출처로 하는 관계가 하나도 없는 기사**를 뜻한다. 이유는 다음 세 가지로 나뉜다.

| 구분 | 기사 수 | 쉽게 설명하면 |
| --- | ---: | --- |
| M4 추출에 성공한 청크가 없는 기사 | **1,356건** | 청크는 만들었지만 해당 기사의 청크가 대기 또는 실패 상태여서 성공한 추출 결과가 없음 |
| 성공한 청크에서 관계가 나오지 않은 기사 | **461건** | 추출은 성공했지만 해당 기사의 성공 청크에서 나온 관계가 없음 |
| 관계는 나왔지만 이번 후보에서 제외된 기사 | **76건** | 관계가 추출됐지만 미결 관계 등으로 제외되어 이번 후보에 남은 관계가 없음 |
| **합계** | **1,893건** | 현재 적재 후보 관계와 연결되지 않은 기사 |

예를 들어 **A 기사**는 청크가 대기 중이라 아직 관계 추출 결과가 없을 수 있다. **B 기사**는 LLM 응답을 정상적으로 받았지만 추출된 관계 목록이 비어 있을 수 있다. **C 기사**는 `미결 제품 → 행사에서 소개되었다 → 미결 행사`라는 관계가 추출됐더라도, 양쪽이 미결인 관계를 이번 범위에서 제외하기로 했기 때문에 적재 후보에 남지 않을 수 있다. 이 예시들은 이해를 돕기 위한 가상의 사례다.

> 기사 기준 **58.7%**는 각 기사에서 나온 관계가 **하나 이상** 후보에 있다는 뜻이다. 해당 기사 내용의 58.7%나 기사 전체가 그래프로 표현된다는 의미는 아니다. 관계 후보가 없는 기사 역시 추출 대기·실패, 관계 미추출, 후보 제외가 섞인 것이므로 모두 활용 가치가 없는 기사라는 뜻은 아니다. 추출에 성공한 청크가 있는 기사라도 일부 다른 청크는 대기 또는 실패 상태일 수 있다.

### 1.2 주요 결과

- **M5의 목적:** 기사와 공시에 나온 개체 중 같은 대상을 가리키는 표현을 대표 개체에 연결하고, 그 개체를 사용하는 관계를 정리한다.
- **뉴스 입력:** M4에서 추출한 개체 언급 29,245건과 관계 기록 20,270건. 전체 뉴스가 아니라 M4 실행이 중단되기 전 **성공한 4,757개 청크**의 결과다.
- **뉴스 처리 결과:** 기존 연결, 인물 처리, 제품·행사·지표 처리를 합쳐 **관계 기록 17,698건**을 이번 적재 후보 범위에 보존했다.
- **별도 관계:** 구조화 재무 관계 14건과 공시 지분 관측 관계 14건, 합계 **28건**을 뉴스와 별도로 보존했다.
- **이번에 제외:** 처음 분류할 때 주어와 목적어가 모두 미결이었던 뉴스 관계 2,539건과 기타 한쪽 미결 관계 33건, 합계 **2,572건**을 이번 적재 후보에서 제외했다.
- **정규화 상태:** 시간 제약을 고려해 이름과 기사 문맥을 이용한 규칙을 유연하게 적용했다. 결과에는 **잠정 연결**, **개별 보존**, **검토 필요** 항목이 포함된다.
- **M5 확인 결과:** 정규화 코드와 전후 ID 연결 기록·사례를 마련하고, 관계의 양 끝 개체와 출처·근거·속성의 보존 여부를 점검했다.

> **완료 범위:** 이번에 사용할 M5 결과를 정리했다는 뜻이다. 미결 항목 전체를 처리했거나 모든 개체·관계의 사실성과 동일성을 사람이 검증했다는 뜻은 아니다. 이 작업에서 AuraDB를 변경하지 않았다.

## 2. M5의 목적과 주요 용어

### 2.1 왜 정규화가 필요한가?

서로 다른 기사에서 같은 회사를 `아모레퍼시픽`과 `㈜아모레퍼시픽`처럼 다르게 표현할 수 있다. 같은 대상을 매번 별도 노드로 만들면 관계가 여러 노드로 흩어져 조회하기 어렵다. **개체 정규화**는 원래의 여러 표현을 검토하거나 규칙에 따라 하나의 대표 개체 ID에 연결하는 작업이다.

반대로 이름이 비슷하다고 무조건 합치면 서로 다른 대상이 하나가 될 수 있다. 예를 들어 같은 이름으로 불리는 **회사와 브랜드는 유형과 역할이 다르므로 구분**한다.

### 2.2 보고서에서 사용하는 말

| 용어 | 뜻 |
| --- | --- |
| **개체** | 회사·인물·브랜드·제품처럼 따로 구분하려는 대상 |
| **개체 언급** | 기사에서 추출한 개체의 한 번의 기록. 같은 대상이 여러 기사에 나오면 여러 언급이 생길 수 있음 |
| **대표 개체 ID** | 같은 대상으로 연결한 언급들이 공통으로 참조하는 식별자 |
| **관계 기록** | 주어·서술어·목적어와 해당 근거를 담은 한 건의 추출 결과 |
| **미결 개체** | 어느 대표 개체에 연결할지 결정되지 않은 개체 언급 |
| **잠정 연결** | 규칙에 따라 대표 ID를 연결했지만 사람이 동일성과 사실을 모두 승인하지 않은 상태 |
| **개별 보존** | 다른 개체와 같은지 판단하지 않고 별도의 ID로 보존한 상태 |
| **검토 필요** | 동일인 여부, 관계 의미, 수치의 대상 등 추가 확인이 필요하다는 표시 |

**개체 언급 수, 대표 노드 후보 수, 관계 기록 수는 서로 다른 수치다.** 예를 들어 같은 인물 언급 여러 개가 하나의 대표 인물 ID로 묶이고, 그 인물이 여러 관계 기록에 등장할 수 있다.

M4 마지막 확인 상태는 성공 **4,757청크**, 실패 **13청크**, 대기 **2,108청크**였다. 위의 실패·대기 2,121개는 두 수의 합이다. 이 수치는 제공된 스냅샷 기준이며 이후 사용자의 컴퓨터에서 실행한 작업은 반영하지 않는다. 따라서 M5의 뉴스 결과는 원래 `news.jsonl` 기사 전체의 정규화 결과가 아니다. M4 중단 내용은 [M4_progress_interruption_report.md](M4_progress_interruption_report.md)를 참고한다.

공시 결과는 2025-12-31과 2026-03-31을 기준으로 각각 7건씩 정리한 관측이다. **공시 제출일, 지분 관측 기준일, 기사 발행일은 서로 다르다.** 지분 관계는 비율의 기준과 관련 주석을 함께 확인해야 한다.

## 4. M5 작업 과정

### 4.1 초기 정규화: 기존 연결 활용과 미결 표시

M4 성공 청크의 개체와 관계를 읽고, 기업 식별 정보·공시 결과·기존 M5 결과를 대조했다. 뉴스에서 이전에 연결한 개체는 그 이력을 함께 보존했다. 연결 근거가 부족한 개체는 임의로 확정하지 않고 **미결**로 남겼다.

초기 결과는 다음과 같았다.

| 초기 확인 항목 | 결과 |
| --- | ---: |
| 뉴스 개체 언급 | 29,245건 |
| 그중 이전 M5 연결을 재사용한 언급 | 10,859건 |
| 미결인 뉴스 개체 언급 | 18,386건 |
| 뉴스 관계 기록 | 20,270건 |
| 양 끝 개체가 기존 자동·잠정 연결된 관계 | 1,905건 |
| 주어·목적어 중 적어도 한쪽이 미결인 관계 | 18,365건 |

여기서 **1,905건은 당시 바로 사용할 수 있는 연결 후보**를 뜻하며, 그 내용이 사람에 의해 모두 검증되었다는 뜻은 아니다. 언급 수는 관계에 등장하지 않는 개체를 포함하므로 관계 수와 일대일로 비교할 수 없다.

### 4.2 미결 관계 분류와 처리 범위 결정

후속 작업의 양이 많아, 미결 관계를 **양쪽 모두 미결인지**, 아니면 **한쪽만 미결인지** 먼저 구분했다. 한쪽만 미결인 관계는 미결 개체의 유형별로 나누었다.

시간을 고려해 사용자가 요청한 대로 **처리 전 양쪽이 모두 미결이었던 관계는 이번 작업에서 제외**했다. 한쪽만 미결인 관계 중에서는 인물부터 처리한 뒤 제품·행사·지표를 처리했다. 나머지 기타 유형의 한쪽 미결 관계는 이번에 제외했다.

### 4.3 인물: 이름과 기사 문맥을 이용한 잠정 연결

원문 청크에 해당 인물명과 시범 대상 7개 기업 중 적어도 한 기업의 이름이 함께 등장하면, 표기를 정리한 인물명이 같은 언급을 하나의 잠정 인물 ID로 연결했다.

| 인물 작업 항목 | 결과 |
| --- | ---: |
| 한쪽 미결 인물 관계 | 771건 |
| 처리한 미결 인물 언급 | 669개 |
| 생성한 잠정 대표 인물 ID | 99개 |
| 함께 연결한 기존 잠정 인물 언급 | 72개 |
| 기존 양쪽 연결 관계 중 인물 ID를 갱신한 관계 | 51건 |

**회장·대표·대표이사는 서로 다른 직책이므로 하나의 유의어로 통일하지 않았다.** 직책은 기존 관계 속성에 보존했다. 같은 이름과 기업이 기사에 나온다는 조건은 실습을 위한 유연한 규칙이며, 동명이인 여부와 실제 직책·관계의 정확성을 증명하지는 않는다.

### 4.4 제품·행사·지표: 같은 이름은 잠정 연결하고 불명확하면 보존

| 유형 | 처리 기준 | 유의할 점 |
| --- | --- | --- |
| **제품** | 표준화한 제품명과 확인된 브랜드를 기준으로 같은 이름을 잠정 연결. 브랜드 정보가 없으면 미상끼리 분류 | 브랜드의 한글·영문 표기는 비교에 활용. 브랜드 미상끼리 묶인 제품은 오병합 가능성이 있으며 브랜드 노드 자체를 병합한 것은 아님 |
| **행사** | 표준화한 행사명과 추출 결과에 **명시된 행사 연도**를 기준으로 잠정 연결 | 행사 연도가 없으면 같은 이름의 서로 다른 회차가 묶일 수 있음 |
| **지표 관측값** | 기존 언급마다 별도 관측 ID로 보존 | 같은 이름이라는 이유로 서로 다른 수치·기간을 합치지 않음 |

제품·행사에서 기준을 충족하지 못한 **제품 6개와 행사 570개**는 다른 개체와 합치지 않고 **각각 별도 노드로 보존**했다. 관계는 이번 후보에 포함되지만 그 개체가 다른 기사에 나온 대상과 같은지는 확인되지 않았다.

지표는 관계 **10,258건**에 기존 지표 언급 **10,256개**가 연결되어 있다. 이 중 지표 2개가 각각 둘 이상의 대상과 연결된 총 관계 4건에는 검토 표시를 남겼다. 자동으로 수치나 대상을 임의 분리하지 않았다.

**데이터 확인 결과:** 새로 만든 잠정 행사 대표 노드 462개 중 **458개**는 연결된 관계의 `event_date` 속성에서 연도를 확인할 수 없어 `연도미상`끼리 묶인 결과다. 코드는 `YYYY-MM-DD` 형식의 관계 속성만 사용하며, 행사 이름이나 기사 발행일에서 발생 연도를 추정하지 않는다. 따라서 같은 이름의 서로 다른 회차가 합쳐질 가능성을 고려해야 한다.

지표 언급 10,256개 중 **190개는 수치**, **920개는 단위**가 추출 속성에 없어 각각 검토 표시가 있다. 두 항목은 겹칠 수 있으므로 단순히 더하지 않는다. 원문에 수치가 있더라도 M4 추출 속성에 빠져 있을 수 있으며, M5는 없는 값을 자동으로 채우지 않았다.

### 4.5 작업 흐름

```text
M4 성공 뉴스 + 기업 식별 정보 + 공시·재무 결과 + 기존 M5 연결
                                ↓
              초기 개체·관계 정규화와 미결 표시
                                ↓
          한쪽 미결 인물 잠정 연결 / 양쪽 미결 관계 제외
                                ↓
        한쪽 미결 제품·행사·지표 처리 / 기타 유형 제외
                                ↓
     뉴스 관계·노드 후보 + 재무·공시 관계 + 매핑·제외 기록
                                ↓
                   M6 입력 매핑 및 적재 시험
```

이 흐름은 수행한 작업의 연결을 설명한다. 기존 단계별 검토 결과가 새 기준으로 모두 사실 검증되었다는 의미는 아니다.

## 5. 정규화 전후 실제 사례

아래 사례는 실제 결과 파일의 ID·관계·출처를 바탕으로 정리했다. 원문 인용은 해당 자료의 내용이며, 이 표 자체가 관계의 정확성을 확정하는 것은 아니다.

### 5.1 인물: 서경배

| 항목 | 처리 전 | 처리 후 |
| --- | --- | --- |
| 인물 표기 | 서경배 | 서경배 |
| 인물 개체 ID | `MENTION-55ec734ea1212dfd0e694ac1` | `PERSON-RULE-f6a2566b625c55579d14` |
| 관계 | 서경배 → 직책을 맡는다 → 아모레퍼시픽 | 같은 관계의 인물 끝점을 잠정 대표 ID로 변경 |
| 직책 속성 | 회장 | 회장으로 보존 |
| 상태 | 미결 | 규칙 기반 잠정 연결 · 검토 필요 |

- **적용 기준:** 같은 청크에 `서경배`와 시범 대상 기업명 `아모레퍼시픽`이 있어 이름 기준 대표 ID로 연결했다.
- **원문 근거:** “아모레퍼시픽(회장 서경배)”이라는 기사의 표현.
- **출처:** [뉴스클레임 기사](https://www.newsclaim.co.kr/news/articleView.html?idxno=3081496), 문서 `NEWS-0d3b7b63da153b2f`, 청크 `NEWS-0d3b7b63da153b2f-C00001`.
- **해석:** 이 관계의 기사 속 직책은 `회장`이다. 다른 기사에서 `대표`라고 표현했다고 해서 두 직책을 같은 의미로 합치지 않는다. 이름 기준 병합의 정확성은 추가 검토가 가능하다.

### 5.2 제품: 여러 기사의 같은 제품명

| 항목 | 기사 A | 기사 B | 정규화 후 |
| --- | --- | --- | --- |
| 제품명 | 듀얼 리페어 리프트 M.D. 크림 미스트 | 듀얼 리페어 리프트 M.D. 크림 미스트 | 같은 표기의 제품 후보 |
| 개체 ID | `MENTION-04cc3e13f00a8d45ac1bf23d` | `MENTION-4618dcdbeb51ffd70fc7e312` | `PRODUCT-RULE-668a26ddb89985f5f2a2` |
| 관계 | 제품 → 브랜드에 속한다 → 에이피 뷰티 | 제품 → 브랜드에 속한다 → 에이피 뷰티 | 두 기사 관계의 제품 끝점을 같은 잠정 ID로 연결 |

- **적용 기준:** 표준화한 제품명과 브랜드 기준이 일치하여 같은 제품 후보로 연결했다.
- **기사 A 근거:** 에이피 뷰티가 해당 크림 미스트를 출시했다고 밝힌 기사. [테크홀릭](http://www.techholic.co.kr/news/articleView.html?idxno=223545), 문서 `NEWS-0fdd2f5d8f821b9a`.
- **기사 B 근거:** 에이피 뷰티가 같은 이름의 크림 미스트를 출시한다고 밝힌 기사. [메트로서울](http://www.metroseoul.co.kr/article/20261105500277), 문서 `NEWS-e03b6b36b84b5050`.
- **주의:** 제품 ID를 합친 것과 별도로, 두 관계의 브랜드 노드가 실제로 동일한 ID인지와 관계 의미는 M6 매핑·검토 단계에서 확인한다. 두 기사의 근거 기록은 각각 보존한다.

### 5.3 행사: 같은 행사명을 대표 ID로 연결

| 항목 | 처리 전 | 처리 후 |
| --- | --- | --- |
| 행사명 | 2026 국회 입법박람회 | 같은 행사명의 잠정 대표 행사 |
| 예시 개체 ID | `MENTION-85e2a93173df655a591a1a41` | `EVENT-RULE-19e7f11aec4a21be0059` |
| 예시 관계 | 아모레퍼시픽 → 행사·활동에 참여한다 → 행사 | 관계의 행사 끝점을 대표 ID에 연결 |
| 함께 보존할 정보 | 행사명·출처·원문 근거 | 동일하게 보존 |

결과에는 기존에 연결되어 있던 행사 관계도 새 행사 ID에 맞춰 정리한 기록이 있다. 예를 들어 [아시아타임즈 기사](https://www.asiatime.co.kr/article/20261105500303)는 국회 입법박람회와 아모레퍼시픽 부스를 함께 언급한다. 원문은 부스의 존재를 설명하며, 추출된 `PARTICIPATES_IN` 관계의 의미는 후속 원문 검토가 가능하다.

행사명에 숫자가 있어도 본문의 추출 속성에 행사 연도가 명시되어 있는지와는 구별한다. 특히 연도가 없는 동일 행사명끼리의 잠정 연결은 서로 다른 회차가 합쳐졌을 수 있다.

### 5.4 지표: 이름이 비슷해도 관측값을 별도 보존

| 항목 | 처리 전 | 처리 후 |
| --- | --- | --- |
| 관측 표기 | 남미 뷰티 분야 브랜드별 키워드 순위 | 해당 원문 언급의 개별 지표 관측 |
| 개체 ID | `MENTION-ab53c17fb63c3026ac378c03` | `OBS-RULE-cbc402d823b45cf40a1f` |
| 관계 | 코스알엑스 브랜드 → 지표가 기록되어 있다 → 관측값 | 같은 관계와 근거를 보존 |

[베이비뉴스 기사](https://www.ibabynews.com/news/articleView.html?idxno=156579)는 남미 지역 최근 30일 뷰티 분야 키워드에서 코스알엑스가 16위였다고 설명한다. 이 예시는 **원문에 나온 내용과 기존 추출 결과의 출처를 보여 주는 것**이다. 코드가 기사에 있는 모든 수치를 새로 채웠다는 뜻은 아니다. 지표의 수치·기간이 추출 속성에 없으면 없는 상태를 유지하며, 필요하면 원문과 대조해 보완해야 한다.

## 6. 최종 처리 현황

### 6.1 뉴스 관계 기록 기준

| 구분 | 관계 기록 수 | 이번 처리 |
| --- | ---: | --- |
| 기존에 양 끝이 자동·잠정 연결 | 1,905 | 기존 결과 유지. 일부 인물·행사 대표 ID 정리 |
| 한쪽 미결 인물 | 771 | 규칙 기반 잠정 연결 |
| 한쪽 미결 제품 | 1,940 | 잠정 연결 또는 개별 보존 |
| 한쪽 미결 행사 | 2,824 | 잠정 연결 또는 개별 보존 |
| 한쪽 미결 지표 | 10,258 | 개별 관측값으로 보존 |
| **이번 뉴스 적재 후보 합계** | **17,698** | 원문 근거와 출처를 보존한 관계 기록 |
| 처리 전 양쪽 모두 미결 | 2,539 | 이번 적재 후보에서 제외 |
| 한쪽 미결 기타 유형 | 33 | 이번 적재 후보에서 제외 |
| **전체 뉴스 관계 기록** | **20,270** | M4 성공 청크에서 추출된 관계 |

17,698건은 전체 뉴스 관계 20,270건의 **약 87.3%**, 제외된 2,572건은 **약 12.7%**다. 이는 **관계 기록 기준**이며, 뉴스 전체 기사나 개체의 처리 비율이 아니다. 같은 관계에 여러 출처가 있으면 여러 기록이 존재할 수 있어 최종 Neo4j 관계 수와 같다고 단정하지 않는다.

### 6.2 개체 언급 기준으로 남은 미결 항목

초기 결과에서 **관계에 등장한 미결 개체 ID 17,189개** 중, 인물·제품·행사·지표 작업으로 14,683개를 잠정 처리했다. 나머지 **2,506개, 약 14.6%**는 이번에 처리하지 않았다.

| 남은 유형 | 미처리 개체 ID |
| --- | ---: |
| 지표 | 1,444 |
| 제품 | 370 |
| 행사 | 215 |
| 인물 | 180 |
| 장소 | 133 |
| 기관·조직 | 62 |
| 회사 | 47 |
| 기타 유형 | 55 |
| **합계** | **2,506** |

이는 **실제 서로 다른 개체의 수가 아니라 초기 미결 언급 ID의 수**다. 같은 실제 대상이 여러 ID로 남아 있을 수 있다. 이 밖에 당시 관계에 등장하지 않은 미결 개체 언급 1,197개를 포함하면 **전체 미결 언급 18,386개 중 3,703개, 약 20.1%**가 처리되지 않았다. 이 비율은 위 관계 기록 비율과 분모가 다르다.

제품·행사 개별 보존 노드 **576개**는 이번 관계 후보에 포함된 별도 검토 대상이다. 처리하지 않은 2,506개에 다시 더해 미결 관계 수처럼 해석하지 않는다. 잠정 연결된 나머지 항목도 정확성이 최종 확정된 것은 아니다.

처리 전 양쪽 미결이었던 관계는 이번 대상에서 제외하도록 고정했다. 그 관계에 등장한 개체 중 일부는 **다른 한쪽 미결 관계**를 처리하면서 잠정 ID가 생겼을 수 있다. 그래도 제외 관계 자체가 자동으로 다시 포함된 것은 아니며, 나중에 양 끝과 관계를 다시 확인한 후 별도 작업으로 포함할 수 있다.

### 6.3 재무·공시와 노드 후보

| 결과 | 수량 | 설명 |
| --- | ---: | --- |
| 구조화 재무 관계 | 14건 | 7개 기업의 재무 지표 관계 후보 |
| 공시 지분 관계 | 14건 | 두 기준일에 각각 7건씩 보존한 지분 관측 |
| **재무·공시 관계 합계** | **28건** | 뉴스 관계 기록과 별도 집계 |
| 이번 범위의 노드 후보 | 12,247개 | 뉴스 관계 및 재무·공시 관계에 필요한 후보. 중복·동일성 확정 전 |

12,247개는 M5 결과 파일의 **노드 후보 수**다. 서로 다른 실제 개체의 확정 수나 AuraDB에 실제 적재된 노드 수가 아니다. 회사·브랜드·인물·제품·행사 외에 지표 관측값도 노드 후보에 포함되어 있다.

## 7. 정규화 코드와 결과물

### 7.1 코드별 역할

| 순서 | 코드 | 입력 | 출력 |
| --- | --- | --- | --- |
| 1 | `resolve_m5.py` | M4 추출 결과, `companies.jsonl`, 공시 결과, 기존 M5 연결 결과 | 초기 `m5_output`: 대표 후보, 언급 매핑, 뉴스 관계, 재무·공시 관계, 미결 기록 |
| 2 | `resolve_persons.py` | 초기 `m5_output.zip`, M4 뉴스 추출 결과 ZIP | 인물 잠정 ID·전후 매핑과 뉴스 관계, 제외 목록 |
| 3 | `resolve_remaining.py` | 초기 `m5_output.zip`, M4 뉴스 추출 결과 ZIP, 2번 인물 결과 ZIP | 제품·행사·지표를 반영한 최종 이번 범위 결과와 제외 목록 |

세 코드는 정규화 단계의 서로 다른 시점에 사용했다. **최종 `resolve_remaining.py`만으로 원래 M4 데이터에서 전체 과정을 처음부터 만드는 것은 아니다.** 1번과 2번의 결과가 입력으로 필요하다. 코드 실행에 LLM API 호출이나 AuraDB 연결은 필요하지 않다.

| `excluded_both_unresolved.jsonl`, `excluded_other_one_sided.jsonl` | 이번에 제외한 관계 ID와 사유. 전체 상세 관계는 초기 M5 결과에서 확인 |

### 7.3 실행 예시

다음은 **이미 초기 정규화와 인물 처리가 끝난 뒤** 마지막 제품·행사·지표 처리를 재현하는 예시다. ZIP에서 `resolve_remaining.py`를 꺼내고, 입력 파일을 지정한 경로에 준비한다. 실제 경로와 파일명이 다르면 알맞게 바꾼다.

```powershell
uv run python .\resolve_remaining.py `
  --m5 .\m5_output.zip `
  --m4 .\M4_news_extraction_4757.zip `
  --person .\M5_person_quick_result.zip `
  --output .\m5_result
```

초기 `resolve_m5.py`와 인물 `resolve_persons.py`의 실행 방법, 입력 경로와 주의사항은 각각의 패키지 `README.md`에 있다. 최종 결과는 이미 생성되어 있으므로 **보고서에서 결과를 확인하기 위해 다시 실행할 필요는 없다.** 재실행할 경우 기존 결과를 덮어쓰지 않도록 별도 출력 폴더를 사용한다.

## 8. 검증 결과와 한계

### 8.1 확인한 내용

- [x] 초기 M5 입력인 M4 성공 청크 4,757개와 공시·기업 기준 자료 확인

- [x] 이번 뉴스 관계의 양 끝 ID에 해당하는 노드 후보가 있는지 확인
- [x] 초기 관계와 비교하여 서술어·관계 속성·원문 인용·출처 정보가 보존되는지 확인
- [x] 재무·공시 관계 28건과 공시 문서·표 행·주석 보존 확인

- [x] 행사 연도와 지표 수치·단위가 추출 속성에 빠진 경우를 집계
- [x] 변경 전 개체 ID와 변경 후 ID, 잠정·검토 상태를 매핑 파일에 보존

이 검증은 **결과의 구조와 기록이 보존되었는지에 대한 확인**이다. 모든 관계가 원문에서 의미상 올바르게 추출되었는지, 모든 잠정 개체가 실제로 같은 대상인지, 모든 정보가 현재도 유효한지 전수 확인한 것은 아니다.

### 8.2 알려진 한계

1. **동명이인과 유사 이름:** 인물명과 대상 기업이 같은 청크에 있어도 실제로 같은 사람이라는 보장은 없다.
2. **행사 회차:** 잠정 행사 대표 462개 중 458개는 추출 관계 속성상 연도미상이므로, 같은 이름의 다른 회차가 합쳐졌을 수 있다.
3. **제품·브랜드 연결:** 제품의 표기 비교에 브랜드 이름을 이용했지만, 서로 다른 브랜드 노드를 모두 합친 것은 아니다. 브랜드를 확인할 수 없는 같은 제품명은 브랜드 미상끼리 묶여 오병합될 수 있다.
4. **개별 보존 및 지표 항목:** 제품·행사 576개는 다른 개체와의 동일 여부가 미확인이다. 지표 2개는 각각 여러 대상과 연결되어 있고, 지표 190개에는 추출 수치가, 920개에는 단위가 없어 검토가 필요하다. 수치·단위 누락 건수는 서로 겹칠 수 있다.
5. **미결과 누락:** 제외한 뉴스 관계 2,572건과 M4 실패·대기 청크는 이번 적재 후보에 포함되지 않는다. 관계가 없다는 것은 실제 사실이 없다는 뜻이 아니다.
6. **공시·재무 해석:** 지분의 기준일과 직접·간접 관계, 보고서 주석, 재무제표 범위와 단위를 함께 확인해야 한다.
7. **적재 형식:** 이번 파일의 노드와 관계 기록이 기존 M6 적재 코드에 바로 호환된다고 확인한 것은 아니다. 여러 출처 및 시간별 지분 관측을 보존할 매핑과 실제 적재 결과 검증이 필요하다.
