## 1. 단계 결과 한눈에 보기

- **대상:** 기업 식별 정보·기본정보·2025년 재무정보·뉴스 JSONL 4개와 추가 공시 보고서
- **기업 자료:** 기업 식별 정보 7건, 기본정보 7건, 재무정보 7건 확인
- **뉴스:** 기사 4,580건을 M4 입력 준비 과정에서 6,878개 청크로 분할
- **추가 공시:** 홀딩스 보고서 2건의 지분 표에서 대상 기업 7개 행씩과 관련 주석을 정리
- **공시 전처리 산출물:** 표 행 청크 14개와 주석 청크 4개

> 이 보고서는 확인한 입력 자료와 문서 전처리 작업을 기록한다.

## 2. M1의 목적과 범위

M1은 수집된 자료를 다음 단계에서 다룰 수 있도록 입력 형태와 출처 정보를 정리하는 단계다. 이번 보고서의 범위는 **시범 프로젝트에서 사용하기로 한 4개 JSONL과 추가 공시의 지분 관계 관련 부분**이다.

뉴스는 전달받은 본문을 M4 실행 코드에서 청크로 나누었다. 공시는 전체 보고서를 모두 추출한 것이 아니라 **연결재무제표 주석의 종속기업 현황 표와 관련 주석**을 선택해 정리했다.

## 3. 사용 자료와 입력 현황

| 자료 | 입력 내용 | 확인 건수 | 사용 방식 |
| --- | --- | ---: | --- |
| `companies.jsonl` | 기업 ID, 입력명, 법인명, DART 기업코드 | 7건 | 기업 식별의 기준 후보 |
| `company_info.jsonl` | 업종, 주요 사업, 상장 여부 등과 출처 | 7건 | 기업 기본정보 |
| `financials.jsonl` | 2025년 매출액·영업이익과 출처 | 7건 | 재무정보. 회계 범위 확인 필요 |
| `news.jsonl` | 기사 ID·제목·URL·발행일·본문·기업 ID | 4,580건 | 본문을 청크로 분할해 M4 입력 |
| 홀딩스 공시 보고서 | 종속기업 표 및 지분율 관련 주석 | 2건 | 별도 공시 표 전처리와 지분 관계 추출 |

뉴스는 전달받은 `news(1).jsonl`을 확인한 결과다. 분석 시 원래 파일 이름은 저장 환경에 따라 `news.jsonl`일 수 있다. 확인한 뉴스 4,580건의 문서 ID는 서로 달랐고 본문이 비어 있는 행은 없었다. 이는 본문의 **존재 여부**만 확인한 것으로, 모든 기사의 품질이나 프로젝트 활용가치를 검증했다는 뜻은 아니다.

## 4. 뉴스 전처리와 청크 구성

M4 실행 코드의 기본 설정에서는 본문을 **최대 2,500자**의 연속 구간으로 나눴다. 가능한 경우 구간 후반부의 빈 줄을 기준으로 나누며, 원문 문자열 자체를 고치지 않고 다음 구간으로 이어서 처리한다. 구간을 중복시키는 방식은 아니다.

각 청크에는 다음을 연결했다.

- `document_id`, `chunk_id`: 기사와 청크 식별자
- `primary_text`: 해당 청크의 본문
- 제목, 원문 URL, 기사 발행일, 관련 기업 ID
- 입력 파일의 행 번호와 본문 내 문자 시작·종료 위치

이 정보는 나중에 추출한 관계를 기사와 원문 구간에 다시 연결하는 데 사용한다. 위 설명은 확인한 `M4_parallel_resume` 코드의 동작을 기준으로 하며, 기사 수집 당시 팀원이 수행한 모든 전처리 과정을 독립적으로 검증했다는 뜻은 아니다.

## 5. 공시 보고서 전처리와 산출물

추가로 확보한 공시 원문 두 건에서 같은 형식의 종속기업 표를 찾아 **투자회사, 피투자회사, 업종, 지분율, 결산일, 소재국**을 행 단위로 정리했다. 대상 7개 기업에 해당하는 행을 각 보고서에서 7개씩 보존했으며, 관련 주석은 각 보고서에서 2개씩 보존했다.

| 구분 | 결과 | 단계상 의미 |
| --- | ---: | --- |
| 보고서 목록 | 2건 | 문서·출처·기준일 기록 |
| 표 행 청크 | 14건 | 공시 표의 대상 행을 원문 위치와 함께 정리 |
| 주석 청크 | 4건 | 사실상 지배력 및 지분율 기준 주석 보존 |

공시 표 전처리 코드, 원문 전후 예시, 재현 방법은 별도 문서 **`M1_disclosure_preprocessing_guide.md`**에 정리한다. 공시 원문과 전체 실행 코드, JSONL 결과는 별도 공시 작업 ZIP을 참고한다.

- **CQ 대조:** 질문별 필요한 정보가 실제로 존재하고 연결 가능한지 확인

- **충돌 관계:** 퍼시픽테크 등 기사와 공시의 표현이 다른 사례를 시점·출처별 검토
