# M2 온톨로지 스키마 · 유형 정의와 연결 규칙

> **특정 산업 분야의 기업 조사 업무를 지원하는 지식그래프 구축**  
> M0 CQ와 M1 공시 표 결과를 반영한 시범 스키마

| 항목 | 내용 |
| --- | --- |
| 버전 | 1.3 · 2026-11-07 (유형·서술어 예시 보완) |
| 범위 | 7개 시범 기업, 관련 개체, 4개 JSONL, 추가 공시 보고서 |
| 기준 | 기존 M2 초안·M3 프롬프트·병렬 M4 검증기·제공된 M5 결과 |
| 상태 | **M2 설계 완료 · M3~M6 구현 및 데이터 적합성 확인 필요** |

## 1. 설계 원칙

- **사용자 질문 우선:** M0 CQ 10개에서 필요한 유형, 관계, 속성과 방향을 정의한다.
- **대상 확장 가능:** 이번에는 7개 기업을 시범으로 사용하며, 관련 홀딩스·외부 기업·인물 등도 포함한다.
- **법인과 브랜드 구분:** 이름이 같아도 회사와 브랜드는 다른 개체다. 동일 법인의 별칭도 문맥과 식별 근거를 확인해 연결한다.
- **직접 관계 사용:** 사용자 결정에 따라 주장(`Assertion`) 노드를 기본 적재 모델에서 사용하지 않는다. 기업 간 등의 관계에 출처와 원문 근거를 연결한다.
- **근거 우선:** 기사 수집 대상 표시나 같은 문서의 단순 동시 출현만으로 관계를 만들지 않는다.
- **시점 보존:** 발행일·관측 기준일·사건일·유효기간을 구분한다. 값을 모르면 비워 두고 추정하지 않는다.
- **스키마와 데이터 구분:** 스키마상 경로가 가능해도 실제 데이터에서 경로가 있거나 정확하다는 보장은 없다.

## 2. 개체 유형

개체는 그래프에서 따로 구분하는 대상이다. 예를 들어 회사와 브랜드는 이름이 같아도 서로 다른 개체다.

아래 12개는 현재 병렬 M4 검증기의 추출 허용 유형이다. `Document`와 `Chunk`는 추출 유형이 아닌 전처리 출처 기록이다.

| 유형 | 설명 | 주요 속성 예시 | 주의 |
| --- | --- | --- | --- |
| `Company` | 사업을 하는 **법인 회사**. 기업의 지분이나 재무정보를 연결할 때 사용<br>**예시:** 주식회사 아모레퍼시픽, 주식회사 이니스프리 | `entity_id`, `name`, `legal_name`, `dart_corp_code`, `industry`, `main_business` | 홀딩스도 Company; CorporateGroup과 구분 |
| `CorporateGroup` | 여러 회사를 포괄해 부르는 **기업들의 집단**. 한 회사인 지주회사와 구분<br>**예시:** 아모레퍼시픽 기업집단 | `entity_id`, `name` | 지주회사와 동일 개체로 자동 병합하지 않음 |
| `Brand` | 소비자가 제품이나 서비스를 구분할 때 사용하는 이름. 회사를 뜻하는 경우와 구별<br>**예시:** 이니스프리 브랜드 | `entity_id`, `name`, `aliases` | 이니스프리 등 회사와 동명일 수 있음 |
| `Product` | 회사나 브랜드가 판매·소개하는 개별 상품<br>**예시:** 에이피 뷰티의 듀얼 리페어 리프트 M.D. 크림 미스트 | `entity_id`, `name`, `variant`, `market` | 국가별·제형별 다른 제품 확인 |
| `Person` | 기업과 관련된 임직원, 주주 등 실제 사람<br>**예시:** 기사에서 아모레퍼시픽 임원으로 소개된 박원석 | `entity_id`, `name` | 동명이인에 추가 식별 근거 필요 |
| `Organization` | 기업 외의 정부기관, 연구기관, 협회 등 단체<br>**예시:** 식품의약품안전처 같은 정부기관 | `entity_id`, `name`, `organization_type` | 법인 회사와 표현상 구분 |
| `Event` | 행사, 제품 발표, 협업 등 특정 시점에 일어난 활동이나 사건<br>**예시:** 2026 국회 입법박람회 | `entity_id`, `name`, `event_type`, `start_date`, `end_date` | 발생 시점과 보도 시점 구분 |
| `Market` | 기업이 활동하는 국가별·제품별 시장<br>**예시:** 한국 화장품 시장과 같이 범위를 정한 시장 | `entity_id`, `name`, `industry`, `scope` | 시장과 지역 구분 |
| `Place` | 국가, 도시 또는 행사가 열린 공간<br>**예시:** 국회 중앙잔디광장 | `entity_id`, `name`, `place_type` | 동명 장소 구분 |
| `MetricObservation` | 매출액처럼 **어떤 대상의 수치**를 기간·단위와 함께 담는 개체<br>**예시:** 아모레퍼시픽의 2025년 매출액 기록 | `entity_id`, `metric_name`, `value_number`, `unit`, `period`, `statement_scope`, `is_forecast` | 재무 범위·단위·시점 확인 |
| `Regulation` | 기업·제품·시장에 적용되는 법령이나 규정<br>**예시:** 화장품에 적용되는 규정 | `entity_id`, `name`, `jurisdiction`, `effective_date` | 특정 제품의 위반을 추정하지 않음 |
| `Character` | 행사나 제품 홍보에 등장하는 가상의 캐릭터. 실제 사람과 구분<br>**예시:** 망그러진 곰 | `entity_id`, `name` | 인물·기업으로 자동 분류하지 않음 |

표의 예시는 유형과 방향에 대한 이해를 돕기 위한 것으로, 모두 검증되어 적재된 결과라는 뜻은 아니다.

위 속성은 **그래프 목표 스키마**다. 현재 M4가 각 속성을 전부 추출하거나 검증한다는 뜻은 아니다. 구조화 입력의 직원 수 등 출처가 불충분한 속성은 확인 전 확정하지 않는다.

## 3. 서술어와 연결 규칙

서술어(Predicate)는 주어(S)와 목적어(O) 사이에서 어떤 연결인지를 나타내는 말이다. 예를 들어 `아모레퍼시픽홀딩스 → OWNS_STAKE → 아모레퍼시픽`에서 `OWNS_STAKE`가 서술어다. Neo4j에서는 이를 관계 유형으로 구현한다.

화살표 왼쪽이 주어(S), 오른쪽이 목적어(O)다. 아래에 없는 유형 조합은 M4에서 허용하지 않는다. 서술어와 방향은 현재 `m4_parallel/run_m4.py`의 `RULES`와 대조했다.

| 서술어 | 출발 유형 → 도착 유형 | 의미와 필요한 조건 |
| --- | --- | --- |
| **직책을 맡는다** `HOLDS_POSITION` | Person → Company, Organization | 인물의 직책·소속. 역할 및 해당 시점은 근거에 있는 경우 기록<br>**예시:** `인물 → 직책을 맡는다 → 아모레퍼시픽` |
| **지분을 보유한다** `OWNS_STAKE` | Company, Person → Company | 투자자·주주에서 피투자회사 방향. 지분율, 기준일, 비율의 기준, 예정·완료 상태 보존<br>**예시:** `홀딩스 → 지분을 보유한다 → 아모레퍼시픽` |
| **기업집단에 속한다** `PART_OF_GROUP` | Company → CorporateGroup | 기업집단 소속. 지주회사의 직접 지분과 혼동 금지<br>**예시:** `회사 → 기업집단에 속한다 → 아모레퍼시픽 기업집단` |
| **브랜드를 운영한다** `OPERATES_BRAND` | Company → Brand | 해당 법인이 브랜드를 운영한다는 명시적 근거 필요<br>**예시:** `회사 → 브랜드를 운영한다 → 브랜드` |
| **브랜드에 속한다** `PRODUCT_UNDER_BRAND` | Product → Brand | 제품이 특정 브랜드에 속함<br>**예시:** `크림 미스트 → 브랜드에 속한다 → 에이피 뷰티` |
| **행사·활동에 참여한다** `PARTICIPATES_IN` | Company, CorporateGroup, Brand, Person, Organization → Event | 참여자에서 행사·활동으로. 역할은 확인 가능한 경우 기록<br>**예시:** `아모레퍼시픽 → 행사에 참여한다 → 국회 입법박람회` |
| **지표가 기록되어 있다** `REPORTS_METRIC` | Company, CorporateGroup, Brand, Market, Product → MetricObservation | 대상의 수치 관측. 관계 이름만으로 대상이 직접 공시했다고 단정하지 않음<br>**예시:** `회사 → 지표가 기록되어 있다 → 2025년 매출액` |
| **지역에 해당한다** `MARKET_IN_PLACE` | Market → Place | 시장이 해당 장소·지역에 관련됨<br>**예시:** `한국 화장품 시장 → 지역에 해당한다 → 대한민국` |
| **장소에서 열렸다** `EVENT_IN_PLACE` | Event → Place | 행사·사건이 장소에서 일어남<br>**예시:** `국회 입법박람회 → 장소에서 열렸다 → 국회 중앙잔디광장` |
| **행사에서 소개되었다** `PRODUCT_FEATURED_IN` | Product → Event | 제품이 기사에 명시된 행사에 등장하거나 소개됨<br>**예시:** `제품 → 행사에서 소개되었다 → 신제품 행사` |
| **캐릭터가 등장한다** `EVENT_FEATURES` | Event → Character | 행사에서 특정 캐릭터가 등장함<br>**예시:** `협업 행사 → 캐릭터가 등장한다 → 캐릭터` |
| **규제 대상으로 삼는다** `REGULATES` | Regulation → Product, Market | 법령·정책의 명시적 적용 대상. 위반 여부는 추론하지 않음<br>**예시:** `규정 → 규제 대상으로 삼는다 → 제품` |

`PRODUCT_FEATURED_IN`, `EVENT_FEATURES`, `REGULATES`와 `Regulation`, `Character`는 옛 M2 초안에서는 신규 제안이었으나, 확인한 **병렬 M4 실행 코드에서는 이미 허용**된다. 옛 시험용 로더까지 이를 지원한다는 의미는 아니다.

## 4. 핵심 관계와 속성

### 4.1 직접 관계의 공통 속성

| 속성 | 목적 | 기록 규칙 |
| --- | --- | --- |
| `relation_id` | 관계 관측값 식별 | 안정적인 ID; 서로 다른 기준일·조건의 관계를 단순 덮어쓰지 않음 |
| `status` | `planned`, `ongoing`, `completed`, `unknown` | 원문 근거가 있을 때만 상태 부여 |
| `event_date` | 사건 발생일 | 발행일로 대체하지 않음 |
| `as_of_date` | 정보·지분율의 기준일 | 보고서 제출일이나 피투자회사 결산일과 구분 |
| `valid_from`, `valid_to` | 관계의 유효기간 | 원문에 명시된 경우만 사용. 관측 두 시점 사이 지속을 추정하지 않음 |
| `review_status` | 자동·잠정·검토 완료 등 | 회사 동일성 및 관계 검토와 별도 관리 가능 |
| `evidence_json` | 출처별 근거 목록의 직렬화 값 | Neo4j 저장용 제안. 배열의 각 항목에 문서 ID·청크 ID·URL·발행일·원문 인용·검토 상태 보존 |

`evidence_json`은 다수 출처를 보존하기 위한 **직접 관계 속성의 제안**이다. 구조화 레코드에는 `source_field`, 공시 표에는 문서 ID·표 위치와 기준일을 포함한다. 관계마다 여러 출처가 다른 조건이나 시점에 대응하면 한 묶음으로 합치지 않는다. 원문과 추출값 간 관계가 불명확하거나 상충하면 검토 대상으로 분리한다.

이 필드 정의는 설계 규칙이며, 기존 M4 출력과 기존 M6 로더가 이 형태를 이미 모두 구현했다는 뜻이 아니다. Neo4j 속성은 중첩 객체 목록을 그대로 속성값으로 저장하지 않으므로 문자열 직렬화 또는 별도 출처 모델 중 구현 방식을 M6에서 검증한다.

### 4.2 지분 관계

`(보유자:Company|Person)-[:OWNS_STAKE]->(대상:Company)`

- 주요 속성: `value_number`, `unit`, `as_of_date`, `percentage_basis`, `status`, `evidence_json`.
- `%`와 주식 수 `주`는 단위가 다르다. 보유 비율의 분모·주식 종류가 다르면 구분하고 임의로 합산하지 않는다.
- 2025-12-31과 2026-03-31의 관측값은 별도 관계 관측으로 보존한다. 지분 보유를 지배력과 동일시하지 않는다.
- 홀딩스→아모레퍼시픽 38.1%의 과반 미만 사실상 지배력 주석, 이니스프리 90.4%의 자기주식 제외 실질지분율 주석을 함께 보존한다.
- 2026-03-31 공시의 홀딩스→퍼시픽테크와 기존 기사 추출의 아모레퍼시픽→퍼시픽테크는 동일 사실로 합치지 않고 원문·시점을 검토한다.

### 4.3 직책·재무 관측

- `HOLDS_POSITION`의 목표 속성 `position`은 원문에 있는 경우에만 기록한다. 현 M4 출력 계약에는 독립된 `position` 필드가 없으므로 `value_text` 등과 원문을 대조해 M5/M6에서 매핑을 정해야 한다.
- 재무 관측에는 `value_number`, `unit`, `fiscal_year` 또는 기간, `period`, `statement_scope`, 출처를 연결한다. 기간이나 회계 범위가 불명확하면 보완 전 비교하지 않는다.

### 4.4 관계 식별 및 다중 출처

같은 S-P-O에 서로 다른 시점·주식 종류·지분율 기준이 있으면 각 관측을 별도로 보관한다. 같은 조건의 동일 관계를 여러 출처가 뒷받침할 때는 한 관계에 근거 항목을 여러 개 연결할 수 있다. `관계 ID`의 구체적인 생성 규칙과 재적재 충돌 처리는 M6 구현에서 정하고 시험한다. 출처별 값이 충돌하면 무조건 병합하지 않는다.

## 5. M0 CQ 10개와 스키마 대조

아래는 **표현 가능 여부**와 기존 M5+공시 후보를 임시로 연결해 살펴본 **구조적 경로 여부**를 구분한 것이다. 기사 관계는 자동·잠정 연결이 포함되고, 시간 조건·원문 의미를 일괄 검증한 결과가 아니다. AuraDB 적재 결과가 아니다.

| CQ | 필요한 개체·관계 | 스키마상 표현 | 현재 데이터 점검 |
| --- | --- | --- | --- |
| CQ01 기업 기본정보 | Company 속성 | 가능 | 7개 구조화 후보. 각 필드 출처 검토 필요 |
| CQ02 2025 재무·근거 | Company → REPORTS_METRIC → MetricObservation | 가능 | 7개 회사·14개 수치 후보. 원문·범위 대조 필요 |

점검 기준: 기존 M5 뉴스 관계 중 양 끝이 `자동연결_미검토` 또는 `잠정_검토필요`인 관계, 구조화 관계, 추가 공시 관계 후보를 사용했다. 같은 시작 ID·서술어·끝 ID는 구조적 경로 확인에서 합쳤고, 날짜·근거의 진위와 유효기간은 경로 계산에 반영하지 않았다. 미결 제외는 확정된 정답이라는 뜻이 아니다. 동일 이름의 다른 ID는 자동으로 합치지 않았다.

## 7. M2 완료 기준

유형 정의·서술어·허용 연결 방향·주요 속성·출처 및 시점 처리 규칙·CQ 대조를 정리했다. 기존 추출 데이터의 **형식적 유형·방향**도 확인했다. 다만 CQ의 실제 정답과 원문 정확성은 추후 M5~M8에서 확인해야 하며, 이 문서는 AuraDB를 변경하지 않는다.
