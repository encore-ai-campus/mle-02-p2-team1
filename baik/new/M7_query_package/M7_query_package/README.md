# M7 · 핵심 질문 조회 및 결과 수집

M6에서 AuraDB에 적재한 **Brian의 데이터셋만 읽어서** 노드·관계 유형과 M0 핵심 질문(CQ) 10개의 연결을 확인한다. 쿼리는 모두 코드에 미리 작성되어 있고, 이 코드는 데이터를 추가·변경·삭제하거나 LLM을 호출하지 않는다.

> 현재 코드를 만든 환경에서는 사용자의 AuraDB에 접근할 수 없으므로 **실제 Cypher 조회와 결과는 아직 확인하지 않았다.** 사용자 PC에서 실행한 뒤 결과를 분석한다.

## 1. 준비와 실행

1. ZIP 압축을 풀고 `M7_query_package` 폴더를 연다.
2. M6에서 사용한 Python 프로젝트와 AuraDB `.env` 설정을 사용한다. `neo4j`, `python-dotenv`가 설치된 환경이어야 한다.
3. PowerShell에서 아래 명령을 실행한다.

```powershell
uv run .\run_m7.py
```

PowerShell을 새로 열어 예전의 인증서 오류가 다시 발생한다면, M6에서 연결할 때 사용한 인증서 경로 설정을 현재 창에서 다시 적용할 수 있다. 모든 컴퓨터에 이 설정이 필요한 것은 아니다.

```powershell
$env:SSL_CERT_FILE = (uv run --with certifi python -c "import certifi; print(certifi.where())")
uv run .\run_m7.py
```

기본 데이터셋은 **`brian_m6_20261108_v1`**이다. M6와 다른 데이터셋 ID로 적재했다면 실제 값으로 지정한다.

```powershell
uv run .\run_m7.py --dataset-id 실제_데이터셋_ID
```

## 2. 어떤 질문을 확인하나?

| 구분 | 조회 내용 |
| --- | --- |
| `STATS_NODES` | 개체 유형별 노드 수 |
| `STATS_RELATIONS` | 관계 유형별 관계 수와 원본 근거 기록 수 |
| `STATS_ISOLATED` | 이번 데이터셋 안에서 관계가 없는 노드 수 |
| `CQ01` | 조사 대상 7개 기업의 정식 명칭·업종·사업 |
| `CQ02` | 7개 기업의 2025년 매출액·영업이익 후보와 출처 |
| `CQ03` | 2026-03-31 공시에 나온 홀딩스→대상 기업 지분 관계 |
| `CQ04` | 같은 기준일에 홀딩스→중간 회사→코스알엑스 지분 관계가 연결되는지 |
| `CQ05` | 선택한 기업에서 직책을 맡은 인물과 관계 근거 |
| `CQ06` | 홀딩스→기업→브랜드←제품 연결 |
| `CQ07` | 홀딩스→기업→행사→장소 연결 |
| `CQ08` | 선택한 인물→기업→브랜드←제품 연결 |
| `CQ09` | 홀딩스→아모레퍼시픽→코스알엑스→브랜드←제품 연결 |
| `CQ10` | 선택한 인물→회사→기업→브랜드→행사→장소 연결 |

CQ05의 기본 기업은 아모레퍼시픽, CQ08·CQ10의 기본 인물은 서경배다. 기사에서 같은 이름의 다른 개체가 있거나 M5에서 연결이 분리되어 있으면 같은 이름의 다른 경로가 보이거나 일부 경로가 빠질 수 있다. 인물과 기업의 동일성도 후속 검토가 필요하다.

CQ03은 2026-03-31과 **공시 출처** 조건을 적용한다. CQ04는 두 지분 관계 모두 2026-03-31인 경우를 찾으므로, 연결이 존재해도 둘 중 하나의 기준일이 없거나 다르면 결과가 나오지 않는다. 0건은 조건에 맞는 **현재 그래프 경로가 없다는 뜻**이지 실제 기업 관계가 없다는 뜻이 아니다.

## 3. 결과 파일

기본 결과는 이 폴더의 `m7_output`에 저장한다.

- `m7_summary.md`: 조회별 성공·오류, 표시된 결과 건수와 표본 한도 초과 여부.
- `m7_results.json`: 사용한 Cypher·파라미터, 결과 노드와 관계, 출처·근거와 개별 조회 오류.

**CQ별 기본 최대 표시 건수는 10개다.** 요약에 표시된 건수는 결과 표본 수이며, 데이터베이스 전체 답변 수가 아니다. 11번째 결과가 있으면 `추가 결과 있음`으로 표시한다. 데이터가 많은 경우 표본이 어떤 순서로 반환되는지는 보장하지 않는다.

조회가 성공했지만 결과가 0건인 경우와, Cypher 오류 등으로 조회가 실패한 경우를 구분해 기록한다. 한 질문에 오류가 나도 나머지 질문은 계속 조회한다. 오류가 있으면 전체 실행은 오류 상태로 종료되며, 성공 결과와 오류 내용은 함께 저장된다.

결과에는 기사 URL·원문 인용과 검토 상태가 포함될 수 있다. 작성자에게 전달하거나 공유 저장소에 올리기 전에는 해당 공유 범위를 확인한다. 비밀번호나 API 키는 결과 파일에 넣지 않는다.

## 4. 다음 단계

조회가 끝나면 `m7_output` 폴더를 ZIP으로 압축해 결과를 전달한다. 폴더 안에 결과가 있으면 이 코드는 덮어쓰지 않으므로, 다시 실행할 때는 다른 출력 폴더를 지정한다.

```powershell
Compress-Archive -Path .\m7_output\* -DestinationPath .\m7_results.zip
```

```powershell
uv run .\run_m7.py --output .\m7_output_2
```

실행 결과에서 각 질문에 사용할 경로·근거를 고른 뒤, Neo4j 그래프 화면에서 보기 좋은 시각화 쿼리와 M7 완료 보고서를 만든다. 경로가 조회됐다는 것 자체는 답변의 사실성을 검증했다는 의미가 아니며, 출처와 시점 대조는 M8에서 수행한다.
