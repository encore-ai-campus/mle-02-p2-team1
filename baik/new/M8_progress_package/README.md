# M8 검증 및 시상식 오병합 보완 안내

## 현재 상태

원문 사본과 M4·M5 결과, 제공된 M7 조회 결과를 대조해 서로 다른 시상식이 하나의 노드로 합쳐진 사례를 확인했다. 교정한 입력과 코드는 로컬에서 검사했으며 **현재 AuraDB에 수정이 적용되었는지는 아직 확인하지 않았다.** 실제 Neo4j에서의 실행과 소요 시간·메모리 사용은 검증되지 않았다.

대상 데이터셋: `brian_m6_20261108_v1`. 다른 데이터셋은 수정 대상이 아니다. 같은 데이터셋에 대한 다른 적재 또는 수정은 종료한 후 실행한다.

## 1. 파일 준비

이 ZIP을 폴더에 풀고 PowerShell에서 그 폴더로 이동한다. 이전 M6 적재에 사용한 Neo4j 접속 설정 `.env`를 이 폴더에 준비하거나 동일한 환경 변수를 설정한다. `.env`와 API 키·비밀번호는 공유하거나 GitHub에 올리지 않는다. Python 환경에는 `neo4j`, `python-dotenv`가 필요하다.

이전에 인증서 경로 설정이 필요했던 컴퓨터라면 같은 PowerShell 창에서 다음을 먼저 실행한다.

```powershell
$env:SSL_CERT_FILE = (uv run --with certifi python -c "import certifi; print(certifi.where())")
```

## 2. DB를 변경하지 않고 사전 확인

```powershell
uv run .\patch_m8.py
```

DB에 접속하여 전체 데이터셋과 대상 노드의 연결을 확인한다. `현재 데이터셋: 변경 전 상태`와 `읽기 확인만 했습니다`가 표시되면 다음 단계로 진행할 수 있다. `이미 변경 후 상태`라면 이미 보완된 상태이므로 4번 검증으로 이동한다. 오류가 발생하면 적용 명령을 실행하지 말고 오류 내용을 확인한다.

## 3. 실제 보완

사전 확인이 성공한 경우 아래 명령으로 적용한다.

```powershell
uv run .\patch_m8.py --apply
```

예전 행사 노드 1개와 관련 관계 5개를 3개 행사 노드와 5개 관계로 바꾼다. 원본 근거 11건은 보존한다. 예상 결과는 노드 12,249개, 관계 13,322개, 원본 관계 기록 17,726건이다.

교정본과 일치하도록 **해당 데이터셋 전체 노드와 관계의 `input_hash` 속성 25,571개도 갱신**한다. 변경과 수정 후 검사는 하나의 트랜잭션에서 수행되며, 실행 전 대상 노드와 관계를 `m8_backup_...json`으로 저장한다. 다른 데이터셋과의 예상 밖 연결이나 추가 속성이 있으면 자동으로 중단한다. 실행이 끊겼거나 결과가 불분명하면 다시 2번 읽기 확인부터 실행한다.

## 4. 수정 후 확인

```powershell
uv run .\load_m6.py --input .\M5_after_M8.zip --verify-only
```

기존 M6 코드로 교정본과 실제 그래프를 비교한다. 이후 M6 코드를 사용할 때도 보정된 ZIP을 입력으로 지정해야 한다. 기존 원본으로 실행하면 입력 지문 불일치로 중단되도록 설계되었다. 기본 원본 ZIP으로 덮어쓰지 않는다.

## 파일 구성

- `M8_progress_report.md`: 검증 범위, 실제 사례, 한계와 남은 일.
- `news_review.md`, `disclosure_audit_cases.json`: 원문·추출·정규화·그래프 대조 기록.
- `m8_event_split_audit.json`: 행사 분리의 근거 기록.
- `M5_before_M8.zip`, `M5_after_M8.zip`: 보완 전후의 M5 결과. 둘 다 보관한다.
- `patch_m8.py`, `load_m6.py`, `mapper.py`: DB 확인·보완과 교정본 검증 코드.
- `correct_event_split.py`, `test_*.py`: 교정본 생성과 로컬 테스트 코드.

뉴스 등 원본 텍스트가 포함된 결과물의 GitHub 공개 여부와 크기는 팀 정책을 확인한다. 비밀번호·`.env`·DB 백업은 공개 저장소에 올리지 않는다.
