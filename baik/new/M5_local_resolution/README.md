# M5 개체 정규화 코드 실행 안내

> M4 뉴스 추출 결과와 공시 지분 추출 결과를 받아, 기존 M5의 잠정 연결을 보존하고 확인되지 않은 개체를 검토 대상으로 남기는 코드.

## 1. 이 코드는 무엇을 하나?

M4의 뉴스 추출 결과와 공시 추출 결과, 7개 기업 식별 정보를 읽어 M5 결과 파일을 만든다. **LLM API나 Neo4j에 접속하지 않는다.**

- 뉴스의 개체가 어떤 문서·청크에서 추출됐는지 확인하고 청크마다 별도인 `local_id`를 구분한다.
- 기업명 일치를 **대표 회사의 후보**로 표시한다. 이름이 같다는 이유로 법인과 브랜드를 합치지 않는다.
- 선택한 경우, 어제 만든 M5 결과의 자동·잠정 연결을 가져오되 **기존 검토 상태를 그대로 유지**한다.
- 뉴스 관계의 주어·서술어·목적어, 속성·기사 원문 근거·출처를 보존한다.
- 공시 관계 14건을 기준일별로 유지하고 공시의 표 행·출처·주석을 함께 저장한다.
- 불확실한 개체와 관계, 검토 가능한 CSV, 정규화 전후 사례를 만든다.

> 결과는 M5의 정규화·검토 후보이다. 자동 연결은 사람이 승인한 결과가 아니며, 이 코드가 AuraDB에 데이터를 적재하지 않는다. M6의 입력 형식에 맞추는 추가 매핑도 필요하다.

## 2. 준비할 파일

이 코드 ZIP을 압축 해제한 폴더에 다음 파일 또는 폴더를 준비한다.

| 이름 | 준비할 내용 |
| --- | --- |
| `resolve_m5.py` | 이 패키지에 포함된 실행 코드 |
| `companies.jsonl` | 이 패키지에 포함된 7개 기업 식별 파일 |
| `m4_output` 또는 `M4_news_extraction_4757.zip` | [뉴스 M4 결과 ZIP](https://chatgpt.com/library?file_id=libfile_73c3255d43748191aadd168dc17f8095&account_id=572db941-93e9-4f5f-a926-7a495084b755) 또는 기존 폴더. `extractions.jsonl`, `structured_entities.jsonl`, `structured_relations.jsonl` 필요 |
| `ownership_disclosure_M1_M5.zip` | [공시 표 추출 결과 ZIP](https://chatgpt.com/library?file_id=libfile_647b2155d8ac819189e30c31022710cf&account_id=572db941-93e9-4f5f-a926-7a495084b755). 압축을 푼 공시 폴더도 사용 가능 |
| `M5_batch_final.zip` | [어제의 M5 결과 ZIP](https://chatgpt.com/library?file_id=libfile_99e3024727b08191bafb81a068643a1b&account_id=572db941-93e9-4f5f-a926-7a495084b755). 기존 잠정 연결을 재사용하려면 필요 |

기업 파일은 정확히 이번 시범 작업에 사용된 7개 기업 기준이다. 공시 결과와 M4 결과가 서로 다른 회사 ID나 법인명을 가리키면 코드가 중단한다.

이 패키지의 `example_before_after.csv`는 실제 입력으로 시험했을 때 생성한 전후 사례다. 기존 자동·잠정 연결은 검토가 필요하며, 예시를 정확도 평가 결과로 해석하지 않는다.

## 3. 먼저 5개 청크로 시험

Windows PowerShell에서 이 폴더를 열고 아래를 실행한다. `--m4`에는 원래 사용자의 컴퓨터에 있는 `m4_output` 폴더를 지정한 예시다. 경로와 파일 이름이 다르면 실제 위치에 맞게 바꾼다.

```powershell
uv run .\resolve_m5.py `
  --m4 .\M4_news_extraction_4757.zip `
  --companies .\companies.jsonl `
  --disclosure .\ownership_disclosure_M1_M5.zip `
  --previous-m5 .\M5_batch_final.zip `
  --output .\m5_test `
  --limit 5
```

- `--limit 5`는 기사 5건이 아니라 **M4에서 성공한 청크 5개**를 뜻한다.
- 시험에서도 기업·재무 기준 결과와 공시 관계는 전체를 읽는다. 제한은 뉴스 청크에만 적용한다.
- 원본 M4가 ZIP이면 `--m4 '.\M4_news_extraction_4757.zip'`처럼 ZIP을 직접 지정할 수 있다.
- 코드와 결과에는 기사 원문 발췌와 출처가 포함될 수 있다. 팀 저장소에 공유할 범위를 확인한다.

## 4. 전체 성공 청크 처리

시험 결과가 정상이라면 `--limit 5`를 빼고 **다른 새 결과 폴더**를 지정한다.

```powershell
uv run .\resolve_m5.py `
  --m4 .\M4_news_extraction_4757.zip `
  --companies .\companies.jsonl `
  --disclosure .\ownership_disclosure_M1_M5.zip `
  --previous-m5 .\M5_batch_final.zip `
  --output .\m5_output
```

M4 성공분 전체와 공시를 다시 읽어 결과를 만든다. M4에서 실패하거나 대기 중인 청크는 추출 결과가 없으므로 이 코드로 정규화할 수 없다. **기존 데이터나 이전 시험 결과를 삭제하지 않는다.** 출력 폴더가 이미 있고 비어 있지 않으면 덮어쓰지 않고 중단한다.

`--previous-m5`를 빼고 실행하는 것도 가능하다. 이 경우 기존 연결을 사용하지 않으며, 뉴스의 개체는 이름만으로 병합하지 않고 각각 미결로 남는다. 어제 작업을 활용하려면 위 예시처럼 `--previous-m5`를 포함한다.

## 5. 생성되는 파일

| 파일 | 내용 |
| --- | --- |
| `summary.json` | 입력 경로·해시, 청크·개체·관계 수와 검토 상태. 입력의 M4 상태 요약을 읽을 수 있다면 함께 기록 |
| `canonical_nodes.jsonl` | 7개 회사와 홀딩스, 재무 지표 등 구조화 기준 개체. 여러 입력의 원본 기록 보존 |
| `news_nodes.jsonl` | 기존 M5의 비구조화 대표 개체 또는 청크별 미결 개체. 대표 ID에 연결된 언급의 상태별 건수 포함 |
| `mention_mapping.jsonl` | 뉴스 개체 원래 표기·청크별 ID·대표 ID·검토 상태·이전 M5 결정 이력 |
| `news_relations.jsonl` | 뉴스에서 추출한 관계와 양 끝 ID·속성·원문 근거·출처·검토 상태 |
| `structured_disclosure_relations.jsonl` | 구조화 재무 관계와 별도 공시 지분 관계. 기준일이 다른 공시 관계는 별도 보존 |
| `disclosure_documents.jsonl` | 공시 문서 ID·URL·기준일·원문 표 위치 |
| `disclosure_chunks.jsonl` | 공시 표 행과 관련 주석 원문 |
| `review_mentions.csv` | 검토할 각 뉴스 개체, 후보 회사 ID, 원문 일부, 검토 결정 입력란 |
| `before_after_examples.csv` | 정규화 전 개체 ID와 연결 후 대표 ID의 예시. 정확도 평가 표본은 아님 |

### 관계 검토 상태 읽기

- **`개체_미결_검토필요`:** 관계의 주어나 목적어에 아직 미결 개체가 있음.
- **`기존자동또는잠정연결_검토필요`:** 양 끝을 이전 M5에서 자동 또는 잠정 연결했지만 사람의 승인은 아님.
- **`관계의미_원문검토필요`:** 양 끝 개체에 사람의 승인 결정이 있더라도 관계 자체와 원문 의미는 별도로 확인 필요.

같은 대표 개체의 언급별 검토 상태가 서로 다를 수 있으므로, 개체의 `mention_status_counts`와 `mention_mapping.jsonl`을 함께 본다. 공시의 원문 대조 상태와 뉴스의 개체 동일성 검토 상태도 서로 다른 항목이다.

## 6. 사람이 검토한 결과를 반영하려면

`review_mentions.csv`에는 모든 미승인 언급이 한 줄씩 들어 있다. **행 수가 전부 실제로 다른 개체 수이거나, 모든 행을 즉시 검토해야 한다는 뜻은 아니다.** 원문 일부가 있어도 전체 문맥은 원본 기사를 확인한다.

검토자가 같은 개체라고 확인한 행만 다음 열을 채운다.

- `representative_id`: 연결할 기존 기준 개체 ID. 예: `COMPANY-AMOREPACIFIC`
- `decision`: 정확히 `승인`이라고 입력
- `note`: 어떤 근거로 판단했는지 기록

뉴스의 브랜드·인물·행사처럼 기존 기준 개체에 없는 경우, 확인한 여러 행에 **같은 새 ID**를 직접 입력할 수도 있다. 예를 들어 `REVIEW-event-001`이다. 반드시 같은 유형끼리만 연결해야 하며 코드가 유형을 검사한다. 서로 다른 개체를 같은 `REVIEW-` ID로 넣지 않는다.

편집한 CSV를 저장하고 **새 결과 폴더**로 다시 실행한다.

```powershell
uv run .\resolve_m5.py `
  --m4 .\m4_output `
  --companies .\companies.jsonl `
  --disclosure .\ownership_disclosure_M1_M5.zip `
  --previous-m5 .\M5_batch_final.zip `
  --decisions .\reviewed_mentions.csv `
  --output .\m5_reviewed
```

검토 CSV에서 `decision`이 빈 행은 적용하지 않는다. 사람이 승인한 개체가 두 관계 끝에 모두 있더라도 **관계 자체의 원문 의미는 별도로 검토**해야 한다.

## 7. 실제 자료로 확인한 결과

제공된 M4와 기존 M5 스냅샷, 공시 ZIP을 넣어 전체 실행을 시험했다.

| 확인 항목 | 결과 |
| --- | ---: |
| 처리한 M4 성공 청크 | 4,757개 |
| 뉴스 개체 언급 | 29,245건 |
| 기존 자동·잠정 연결 재사용 | 10,859건 |
| 여전히 미결인 뉴스 개체 언급 | 18,386건 |
| 뉴스 관계 | 20,270건 |
| 양 끝이 기존 자동·잠정 연결인 뉴스 관계 | 1,905건 · 사람 검토 필요 |
| 양 끝 중 미결이 있는 뉴스 관계 | 18,365건 |
| 구조화 재무 관계 + 공시 지분 관측값 | 28건 = 14건 + 14건 |

개체 언급·관계는 기사마다 반복될 수 있어 고유한 회사 수나 최종 그래프 관계 수가 아니다. **1,905건을 자동으로 정확하다고 확정하거나 AuraDB에 적재하지 않는다.** 시범 적재에 사용할지, 어떤 검토를 할지 별도로 결정해야 한다.

전체 뉴스 관계 20,270건의 서술어·속성·원문 인용·출처 정보가 M4 입력과 일치하는지 확인했고, 공시의 두 기준일별 7건과 주석 4건이 보존되는지도 확인했다. 원문에 인용이 포함되어 있다는 검사는 관계의 의미와 사실을 증명하지 않는다.

## 8. 참고 사항

- 외부 파이썬 패키지는 필요 없다. 표준 라이브러리를 사용한다.
- 공시 보고서는 입력된 결과를 읽는다. 이 코드는 공시 원본 HTML을 다시 추출하지 않는다.
- 입력된 기존 M5와 M4의 원래 개체, 서술어, 속성, 인용문, 양 끝 언급 및 출처 메타데이터가 다르면 중단한다. 그래도 과거 정규화가 정확하다는 보장은 아니다.
- 결과 폴더의 `review_mentions.csv`와 JSONL에 기사 일부와 URL이 들어가므로 외부에 공개하기 전에 공유 범위를 확인한다.
