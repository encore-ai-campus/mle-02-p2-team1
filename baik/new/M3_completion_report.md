## 1. 단계 결과 한눈에 보기

- M0의 기업 조사 목적과 CQ 10개, M2의 개체·서술어 규칙을 기준으로 **뉴스 청크 추출 프롬프트를 새로 작성**했다.
- **개체 유형 12개와 서술어 12개**의 의미·허용 방향을 명시했다.
- 관계의 출처가 되는 **연속된 원문 근거**, 미확인 정보의 처리, 날짜·지분율·예정 여부를 구분하는 규칙을 넣었다.
- 기존 병렬 M4 코드가 요구하는 JSON 키와 속성 형식에 맞췄다.
- 손으로 작성한 예시를 기존 검증기에 넣어 정상·빈 결과 및 오류 사례를 확인했다. **실제 LLM API 호출과 새 뉴스 추출은 하지 않았다.**

> 기존 M4에서 성공한 4,757개 청크의 추출 결과는 이전 프롬프트로 생성된 결과다. 새 프롬프트를 작성해도 기존 결과가 자동으로 바뀌지는 않는다.

## 2. M3의 목적과 입력 범위

M3는 LLM에 원문을 전달할 때 **무엇을 추출하고 어떤 형식으로 반환해야 하는지** 정하는 단계다.

이번 프롬프트의 입력은 뉴스 기사 전체가 아니라 기사에서 나눈 **개별 청크의 `primary_text`**다. 입력의 문서 ID와 청크 ID는 출력에 그대로 담는다. 제목·기사 발행일·URL·`company_ids` 등은 식별과 참고 정보이며, 본문에 없는 관계의 근거로 사용하지 않는다.

기업 기본정보·재무정보 JSONL과 추가 공시 표에는 구조화된 정보가 있다. 공시 지분 관계는 이미 규칙 기반으로 처리했으므로, 이번 프롬프트를 만들었다고 공시 전체를 LLM으로 다시 추출하는 것은 아니다.

## 3. 프롬프트에 반영한 핵심 규칙

### 3.1 추출 대상

시범 대상 7개 기업과 직접 관련된 다른 회사·인물·브랜드·제품·행사 등 원문에 명시된 정보를 추출한다. 지분·재무·제품·시장·인물·행사뿐 아니라 기사에 실제로 등장하는 다양한 영역을 살핀다.

CQ는 필요한 정보가 무엇인지 알려주는 기준이다. **CQ에 나온 사실만 추출하거나, 여러 홉의 경로를 만들기 위해 원문에 없는 연결을 생성하지 않는다.**

### 3.2 개체와 서술어

| 구분 | 허용 항목 |
| --- | --- |
| **개체 유형 12개** | `Company`, `CorporateGroup`, `Brand`, `Product`, `Person`, `Organization`, `Event`, `Market`, `Place`, `MetricObservation`, `Regulation`, `Character` |
| **서술어 12개** | `HOLDS_POSITION`, `OWNS_STAKE`, `PART_OF_GROUP`, `OPERATES_BRAND`, `PRODUCT_UNDER_BRAND`, `PARTICIPATES_IN`, `REPORTS_METRIC`, `MARKET_IN_PLACE`, `EVENT_IN_PLACE`, `PRODUCT_FEATURED_IN`, `EVENT_FEATURES`, `REGULATES` |

M2와 같은 방향을 사용한다. 예를 들어 `OWNS_STAKE`는 **지분을 보유한 회사 또는 인물 → 지분 대상 회사** 방향이다. 같은 이름의 회사와 브랜드도 서로 구분한다.

### 3.3 원문 근거와 정보가 없는 경우

- 관계마다 입력 청크에 실제로 있는 **연속된 원문 문자열**을 `evidence.quote`에 기록한다.
- 원문에 없는 관계, 지분율, 직책, 기준일은 추정하지 않는다.
- 회사 이름이 함께 등장한다는 사실만으로 지분·협업 관계를 만들지 않는다.
- 추출할 개체나 관계가 없으면 해당 배열에 `[]`를 사용한다.
- 개체는 확인되지만 관계를 확인할 수 없다면 개체만 출력할 수 있다.

관계는 주어·서술어·목적어로 표현한다. 사용자가 결정한 바에 따라 이 프롬프트는 `Assertion` 주장 노드를 별도의 추출 개체로 만들지 않는다.

### 3.4 지분·시간·상태

| 확인 항목 | 프롬프트 처리 기준 |
| --- | --- |
| **날짜** | 원문에 연·월·일이 명확할 때만 `YYYY-MM-DD`로 기록. 기사 발행일을 지분 기준일이나 사건 발생일로 추정하지 않음 |
| **계획 여부** | 예정은 `planned`, 진행 중은 `ongoing`, 완료가 명시되면 `completed`, 불명확하면 `unknown` |
| **지분율·주식 수** | `%`와 `주`를 구분. 과거 인수 비율을 현재 보유 비율로 변경하지 않음 |
| **직접·간접 관계** | 다른 회사의 자회사라는 사실만으로 특정 회사의 직접 보유 관계를 추정하지 않음 |
| **직책** | 원문에 직책이 명시된 경우 `HOLDS_POSITION`의 `value_text`에 기록 |
| **정보 없음** | 확인되지 않은 속성은 `null`. 숫자는 임의로 0을 넣지 않음 |

### 3.5 결과 형식

프롬프트는 기존 병렬 M4 검증기에 맞춰 다음 구조를 요구한다.

| 필드 | 의미 |
| --- | --- |
| `document_id`, `chunk_id` | 입력 문서와 청크의 식별자 |
| `entities` | 청크에서 추출한 개체 목록 |
| `relations` | 개체 간 주어·서술어·목적어 관계 목록 |
| `attributes` | 수치, 단위, 시점, 상태 등의 속성 |
| `evidence.quote` | 해당 관계를 뒷받침하는 청크 원문 |

각 관계의 `subject_id`와 `object_id`는 반드시 같은 응답의 `entities`에 존재해야 한다. 현재 M4 검증기는 허용되지 않은 필드를 거부하므로, 프롬프트에서도 정해진 키 외의 출력 필드를 요구하지 않는다.

## 4. 적용 및 검증 결과

### 기존 M4 코드와의 형식 대조

| 확인 항목 | 결과 |
| --- | --- |
| 개체 유형 12개 | 기존 병렬 M4 `ENTITY_TYPES`와 일치 |
| 서술어 12개와 방향 | 기존 병렬 M4 `RULES`와 일치 |
| JSON 최상위 키 | `document_id`, `chunk_id`, `entities`, `relations`에 맞춤 |
| 개체·관계 속성 키 | 기존 `validate()`가 요구하는 키에 맞춤 |
| 근거 형식 | `evidence.quote`의 청크 원문 포함 규칙에 맞춤 |

### 검증기에 넣어 본 수동 사례

실제 모델이 만든 응답이 아니라, 형식 검사를 위해 **직접 작성한 가상 응답**이다.

| 시험 사례 | 결과 |
| --- | --- |
| 지분 취득이 예정됐다는 문장과 `planned`를 담은 정상 JSON | 통과 |
| 추출 대상이 없어 개체와 관계가 모두 빈 배열인 JSON | 통과 |
| 허용되지 않은 서술어 | 거부 |
| 개체 유형과 맞지 않는 관계 방향 | 거부 |
| 청크에 없는 원문 근거 | 거부 |
| 허용되지 않은 추가 출력 필드 | 거부 |

검증기는 예를 들어 근거 문장이 청크에 들어 있는지와 유형·방향을 확인한다. **그 문장이 관계를 실제로 뒷받침하는지, 날짜나 예정 상태의 해석이 맞는지까지 자동으로 보증하지는 않는다.** 위 시험은 프롬프트가 실제 모델에서 잘 작동하는지 검증한 결과도 아니다.

## 5. 기존 M4·M5 결과를 사용할 때의 구분

| 자료 | 취급 방법 |
| --- | --- |
| 기존 M4 성공 결과 4,757청크 | 이전 프롬프트로 생성된 결과임을 유지하고 재사용 여부와 품질을 점검 |
| 기존 M4 실패·대기 청크 | 추출이 끝나지 않은 입력. 후속 처리 여부와 범위를 별도로 결정 |
| 기존 M5 정규화 결과 | 기존 M4 결과를 바탕으로 생성된 후보. 회사 동일성·시점·근거를 확인한 뒤 필요할 때 재사용 |
| 추가 공시 지분 결과 | 규칙 기반으로 추출한 별도 결과. 기존 기업 ID와의 연결 및 출처·시점 보존 확인 필요 |
| 새 M3 프롬프트 | 앞으로 새로 시도하는 추출에 사용할 기준. 이전 결과를 소급 변경하지 않음 |

기존 병렬 M4 코드는 **프롬프트를 포함한 실행 설정의 해시를 확인**한다. 따라서 새 프롬프트를 기존 진행 폴더에 넣고 그대로 이어 실행하면 설정 불일치로 중단된다. 새 출력 폴더를 사용하면 기본적으로 기존 성공 결과를 자동으로 건너뛰는 것도 아니므로, 미처리분만 새 프롬프트로 실행해 기존 결과와 합치려면 별도의 대상 선정·결과 통합과 중복 방지 방법을 M4에서 마련해야 한다.
